# RM-190 Rename rules: `charts-deprecated-usage`, `chart-default-prose`, `charts-group-drift`; the 6.0 tripwire

## Finding

- Internal callers (WaterfallChart → BarChart, AutoChart → families, ChartMultiples) would pass old names and fire dev warnings in consumer apps for code they never wrote, unless non-test chart source is scanned too.
- Documented defaults drifted from code seven times (F36); with the snapshot holding the real defaults, a rule can keep TSDoc honest.
- Without a ratchet, new family props could re-introduce what a group already owns.
- The removal at 6.0 needs a guard that fails if an alias outlives its `removeIn`.

## Change

- `charts-deprecated-usage` reads the alias rows from the snapshot and flags old names in stories, docs, templates and non-test `packages/charts/src`.
- `chart-default-prose` compares every TSDoc `Default:` against the snapshot default.
- `charts-group-drift` flags family keys that duplicate a group key; the baseline only shrinks.
- The tripwire test reads the charts package version: at ≥ 6.0.0 it fails while any alias row remains or while `ChartSelection`, `ChartBrushLayout`, the `height` aliases or Scatter `trend` still exist — and nothing else (not every `@deprecated` tag).

## Acceptance

- Fixtures for each rule (`pnpm check:test`).
- All three rules green on `charts/unification`.
- The tripwire passes on 5.x and fails on a seeded 6.0.0 version with a remaining row (test).

## Test / gate

`pnpm check:test`, `pnpm check --rule charts-deprecated-usage,chart-default-prose,charts-group-drift`, `pnpm --filter @elabs-ai/components-charts test`, `pnpm gen && pnpm gen:check`.

## Orchestrator notes

The plan lists the 6.0 tripwire under gates without an owning item; it lands here so it exists before the first rename ships.
