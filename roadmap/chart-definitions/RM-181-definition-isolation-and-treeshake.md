# RM-181 Rule `charts-definition-isolation` and the post-build tree-shake check

## Finding

- Bundlers do not drop unused object fields, and `sideEffects: false` does not help once a module is imported: if a family imports the whole registry, every definition, contract and prose string ships in every consumer bundle.
- A curried top-level `defineChart<P>()(def)` call is retained unless marked pure.

## Change

- `charts-definition-isolation` fails a family importing another family's definition or the registry.
- `check-chart-treeshake.mjs` builds a BarChart-only entry and a `./test` entry with esbuild, reads the metafile inputs and reports the bytes of each family's definition plus its groups against a budget.
- If a family exceeds the budget, it splits into `<id>.defaults.ts` (runtime defaults and alias rows) and `<id>.definition.ts` (meta, contract, targets).
- `ci.yml` runs the script in the "Built-output checks" step.

## Acceptance

- A seeded `bar-chart.tsx → registry` import fails both checks (rule fixture; a seeded run of the script documented in the PR).
- A BarChart-only bundle contains no other definition, no registry and no AutoChart.
- The `./test` bundle contains no visx, d3 or motion.

## Test / gate

`pnpm check:test`, `pnpm check --rule charts-definition-isolation`, `pnpm build && node packages/cli/scripts/check-chart-treeshake.mjs`.
