# RM-172 Check rule `charts-definitions-pure`

## Finding

- Definitions and prop groups are read by the test double, the gen step and every family, so they must stay free of React, visx, d3 and motion. Several modules a definition would naturally import are impure today: `chart-breakpoint` (React, ui `cn`), `chart-context` (`@visx/scale` via `y-axis-scales`), `chart-a11y` (ui), `legend/use-container-legend`, `annotations/with-chart-annotations`, `layout-size` (react-use-measure).
- `verbatimModuleSyntax` keeps `import { type X }` as a side-effect import, so only a top-level `import type` is erased.
- The rule must exist before the leaves move (RM-173), so the move is checked, not trusted.

## Change

- `charts-definitions-pure` walks the runtime import closure of `packages/charts/src/definitions/**` and `packages/charts/src/charts/props/**` with `findRuntimeImportSpecifiers` (`scripts/check/rules/charts-test-double.mjs:43`) and allows only an allow-list of pure modules plus `@elabs-ai/components-ui/definition`.
- A mixed `import { type X, Y }` or a side-effect `import { type X }` in those trees fails; top-level `import type` passes.
- `*.test-d.ts` is exempt (the lockstep assertions live there).

## Acceptance

- Fixtures: a seeded runtime import of `chart-breakpoint` from a definition fails; `import type` from it passes; a `*.test-d.ts` importing the registry passes.
- Green on the branch with baseline `none`.
