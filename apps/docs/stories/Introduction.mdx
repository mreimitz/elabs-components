# brand-ui

A **source-owned, token-driven** React component system for building real
applications — dashboards, data grids, AI chat clients, node canvases, maps, code
editors, terminals and the marketing page in front of them. Most component
libraries give you buttons and inputs, then leave you to invent the hard parts.
brand-ui ships the hard parts, all rendered through **one semantic token
system**, so re-branding the entire surface is a stylesheet change — never a
component change. The default look is modern enterprise SaaS — restrained,
app-first, and themeable to any brand.

It is also built to be **read by coding agents**: a CLI, a generated manifest and
a hosted MCP server expose the real props, intent and tokens, so an assistant
extends the system from ground truth instead of guessing.

## Four ways in

- **Build an app now:** `npx -y @elabs-ai/components-cli create my-app --template dashboard`
  — a runnable Vite + React app with tokens, Tailwind and a template screen wired
  (`data-app`, `ai-assistant`, `flow-workspace`, `settings`, `marketing` too).
- **Add it to an app you have:** [Getting Started](?path=/docs/docs-getting-started--docs) —
  `pnpm add`, two lines of CSS, one provider.
- **Point your coding agent at it, nothing to install:**
  `claude mcp add --transport http brand-ui https://elabs-ai.com/mcp` — see
  [brand-ui MCP Server](?path=/docs/docs-brand-ui-mcp-server--docs). Every component
  page below carries the same intent block the agent reads.
- **Choose the right component:** [Choosing between similar components](?path=/docs/docs-choosing-between-similar-components--docs).

## Theming

Pick a theme family with the **Theme** toolbar control (Default, plus the
downloadable families such as Ocean, Qlik and Snowflake) and flip **Mode**
between light and dark. Themes are driven entirely by `data-theme` +
semantic tokens defined in `@elabs-ai/components-tokens/themes.css`. Components never hardcode
colors — they reference tokens like `bg-background`, `text-muted-foreground`,
`border-border`, so re-branding (e.g. swapping the primary hue) is a token change.

## Two ways to consume

### 1. Import stable primitives

```sh
pnpm add @elabs-ai/components-tokens @elabs-ai/components-ui
```

```tsx
import { Button } from "@elabs-ai/components-ui";
```

Each package links from [npm](https://www.npmjs.com/org/elabs-ai); for example
[`@elabs-ai/components-ui`](https://www.npmjs.com/package/@elabs-ai/components-ui).

### 2. Copy-own prototype blocks from the registry

Blocks and templates live in the brand-ui shadcn-compatible registry
([source](https://github.com/mreimitz/elabs-components/tree/main/registry)). Install
one by its full URL:

```sh
npx shadcn@latest add https://mreimitz.github.io/elabs-components/r/latest/data-table.json
```

Or register the `@brand-ui` namespace once in your app's `components.json` and
install by name:

```json
{
  "registries": {
    "@brand-ui": "https://mreimitz.github.io/elabs-components/r/latest/{name}.json"
  }
}
```

```sh
npx shadcn@latest add @brand-ui/data-table
```

Swap `latest` for a release version (e.g. `4.2.0`) to pin a block.
