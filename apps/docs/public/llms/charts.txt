# @elabs-ai/components-charts

> MetricCard, MetricGrid, ChartCard, ChartFrame (expand/flip/download).

Import from `@elabs-ai/components-charts`. Part of brand-ui — see the root `llms.txt` for routing.

## Components

- Area
- AreaChart — Cumulative or part-of-whole trend over time — a filled line.
  - avoid: Stacking areas that are not parts of one whole — a stack asserts summation; use lines.
  - avoid: Overlapping opaque areas — either stack them or switch to a LineChart.
  - avoid: Leaving status="loading" unhandled — AreaChartLoading is the shipped skeleton.
- AreaChartLoading
- AutoChart — Spec-driven chart — hand it a serializable ChartSpec and it picks and renders the right chart.
  - avoid: Hand-picking a chart type when the spec already encodes the intent — AutoChart is the agent-facing entry point.
  - avoid: Putting raw colors in a spec's series — the chart-1…chart-5 tokens are the palette in every theme.
  - avoid: Passing an empty dataset with no not-ready signal — render the loading state instead of an empty frame.
- Bar
- BarChart — Categorical comparison — composed from Bar + BarXAxis/BarYAxis inside its provider.
  - avoid: Truncating the value axis so small differences look large — a bar axis starts at zero.
  - avoid: Hardcoding series colors — use the chart-1…chart-5 tokens so every theme works.
  - avoid: Rendering an empty frame before data arrives — use the shipped chart skeleton utilities.

- ChartConfigProvider
- ChartDatapointLayer — The keyboard/AT half of the chart interaction contract — real buttons in a sibling layer over the aria-hidden chart SVG (#349).
  - avoid: Putting tabIndex on an SVG shape instead — every chart body is aria-hidden, so a focusable child inside it is the axe aria-hidden-focus violation, and axe is blocking here.
  - avoid: Letting the layer take pointer events — it is pointer-events:none so the SVG underneath keeps mousemove; swallowing them silently kills hover tooltips on line/area charts.
  - avoid: Giving every datapoint its own tab stop — the layer is a roving tabindex (one target at 0, the rest -1, arrows to move); a 500-point series must not add 500 tab stops.
  - avoid: Measuring target geometry with getBBox/getBoundingClientRect — targets carry the geometry the shapes already computed from the scales; a layout read in render is the banned path.
- ChartDatapointProvider — Opt-in wrapper that makes a chart's datapoints activatable — mounted only when the consumer passes onDatapointClick or copyValueOnActivate.
  - avoid: Mounting it around every chart by default — a chart with no drill-down handler adds no context, no layer and no DOM, and that opt-out path is the point.
  - avoid: Rendering more than ~500 targets — the provider warns in dev because a keyboard target per datapoint stops being navigable long before it stops rendering.
  - avoid: Reading the click handler out of a state variable that changes every render — the provider keeps the context value stable via refs so an inline arrow function does not churn every shape.
- ChartFallback
- ChartFrame — Opt-in chart wrapper adding expand / flip-to-table / download-CSV to any chart child.
  - avoid: Expecting ChartFrame to read the chart's context — it is the PARENT of the chart's provider; pass the same data to both via props.
  - avoid: Importing @elabs-ai/components-data into a chart — charts → ui only; flip-to-table uses the @elabs-ai/components-ui Table.
  - avoid: Expecting the table/download controls with no `data` — they hide by design when data is absent or empty; pass the same rows you gave the chart.
- ChartLegend — Series key with label, value and an optional progress bar; pattern-aware under decoration.
  - avoid: Dropping the legend on a multi-series chart — colour without a key is not a legend.
  - avoid: Ordering legend items differently from the series — the eye maps them positionally.
  - avoid: Passing a raw hex as the item colour — resolve the chart token so high decoration gets its pattern swatch.

- DrawPath — A path that draws itself in through pathLength 1 — no measurement step, and a real reduced-motion branch rather than a shorter duration.
  - avoid: Filling it — a dash offset acts on the stroke, so a filled path appears in a single frame and the draw-in does nothing at all.
  - avoid: Measuring the geometry with getTotalLength to drive the animation — pathLength 1 exists to avoid it. That measurement is a layout read in render, and it returns 0 under jsdom, so every mocked test would draw nothing.
  - avoid: Shortening the duration instead of branching for reduced motion — a motion path at duration 0 still leaves the dash attributes in the DOM, and a stroke carrying a dash array is one rounding error away from a visible seam. The reduced-motion state has to be the ordinary, undecorated path.
  - avoid: Letting meaning depend on the animation having run — a reader who arrives after it finished, or who never sees it, must lose nothing.
- FunnelChart — Stage-by-stage drop-off through an ordered pipeline.
  - avoid: Using it for unordered categories — a funnel asserts a sequence; unordered data belongs in a bar chart.
  - avoid: Encoding stage identity by colour alone — label each stage; colour is not a legend.
  - avoid: Hiding the absolute counts behind percentages only — a funnel without its base number cannot be judged.
- Gantt (density=comfortable*|compact) — Schedule grid — tasks as bars over time, with a task table beside them.
  - avoid: Mutating task dates inside the component on drag — Gantt is emit-only; the app owns the model (D5).
  - avoid: Bar labels that rely on the bar fill for contrast — check the label against the bar color in every theme.
  - avoid: Rendering the grid without `loading` while rows are still fetching — skeleton rows must hold the layout.

  - avoid: A gauge per KPI in a grid — a row of dials reads worse than a MetricGrid; use one for the headline only.
  - avoid: Encoding the threshold by colour alone — pair the band with a label or a tick.

- HairlineFloor — One tick per calendar period along the foot of a plot, every n-th drawn longer — the passage of time in 0.55px of ink, with nothing to read.
  - avoid: Decimating the ticks to make them fit — one tick per period, always. An irregular floor reads as missing data, and dropping ticks silently costs the reader the duration the mark exists to show. Too many periods to draw means the chart is too small for this mark.
  - avoid: Using it where the reader needs to know WHICH date — a floor answers how long, an axis answers when. If labels are wanted the answer is XAxis, not a longer floor.
  - avoid: Choosing every for looks — the long tick is the only navigational cue on the mark, so it has to land on a boundary the reader already holds: 12 for months, 7 for days, 4 for quarters.
  - avoid: Painting it at series weight — at var(--chart-foreground) the floor stops being a rule and becomes a second data row along the bottom.
- HaloText — SVG text that punches a plot-ground halo out from behind itself, so a label stays readable directly ON a mark instead of beside it.
  - avoid: Hard-coding a paper colour for the halo — the halo IS the plot ground, so a literal white one becomes a white smear the moment the theme goes dark. It defaults to var(--chart-background) for that reason; an override names another token, never a colour.
  - avoid: Reaching for it to rescue low-contrast text — the halo separates a label from BUSYNESS, not from its ground. The ink still has to clear 4.5:1 against the card; a halo over a 3:1 label is still a 1.4.3 failure.
  - avoid: Widening the halo until labels stop colliding — the visible outline is half the width, so a wide one starts eating glyph counters and neighbouring letters. Move the label or drop one; 3px is the calibrated value.
  - avoid: Letting it carry the only copy of a number — the chart body is aria-hidden, so a halo label reaches no screen reader. Repeat the figure in the caption, the summary or the flip-to-table view.
- HeatmapChart
- Leader — The dashed hairline that ties an annotation to the mark it describes — an elbow or a curve, in one of two dash rhythms.
  - avoid: Thickening it so the connection is easier to follow — at series weight a leader stops being furniture and starts being read as data. If it is hard to follow, the label is too far away.
  - avoid: Inventing a third dash rhythm — the union is 1 3 (quiet) and 2 3 (emphatic) on purpose. Sixty-three templates each picking their own dash array is the drift this layer exists to prevent.
  - avoid: Copying the path but not the unset fill — an elbow is an OPEN path, and an open path that is filled paints a solid triangle between its two ends. The component sets it; hand-rolled copies routinely do not.
  - avoid: Routing it across the series it points at — at this weight a leader that overlaps the data is indistinguishable from a gridline. Bend the elbow around instead.

- PeakRing — A dashed outline around the one mark that matters — the peak, the outlier, the cell the caption is about.
  - avoid: Swapping the dash for a highlight hue — the ring exists because emphasis by SHAPE survives greyscale and a colour-blind reader (WCAG 1.4.1). Recolouring it throws away the only reason to reach for it.
  - avoid: Ringing three marks — the ring points at whatever the caption is about. A second ring halves the emphasis and a third deletes it.
  - avoid: Treating the ring as the statement — it is aria-hidden furniture that points; it says nothing. A peak worth ringing is worth writing in the caption or the summary.
  - avoid: Dashing a plotted mark elsewhere in the same chart — nothing that carries data is dashed here, and that is precisely what stops the ring being read as a series.

- QuietDot — The 0.9px pinprick that renders a measured null or zero, so an empty cell in a matrix is never a hole.
  - avoid: Scattering it as decoration — it has ONE job, and it is the null/zero render. A pinprick that is not standing for an absent value teaches the reader that absence is noise.
  - avoid: Leaving a zero cell blank instead — blank reads identically to no data collected, to the grid ends here, and to a rendering bug. The dot says the cell was visited and the answer was nothing.
  - avoid: Assuming it distinguishes 0 from null — it says MEASURED, not which. Where the difference is load-bearing keep the dot for the zero, give the missing cell a hatch or an explicit gap, and say so in the legend.
  - avoid: Enlarging it so it is easier to see — an absence rendered at the weight of a value becomes a value.

- StaticChartPreviewProvider
- UnitStack — n countable marks — rungs, ticks or dots — so a quantity is COUNTED rather than compared; the jitter is seeded, never random.
  - avoid: Passing a large n and calling it a bar — past roughly 60 units the stack stops being countable and becomes a texture, at which point a bar is the honest mark. It will happily draw 500; that is your judgment, not its.
  - avoid: Reaching for Math.random to jitter — use seededRnd. Random jitter makes the chart a different picture on every render, so no snapshot, visual-regression shot or play-function assertion can ever agree with itself.
  - avoid: Giving every stack the same seed — neighbouring stacks then jitter in lockstep and the irregularity reads as a pattern, which is worse than no jitter at all. Vary the seed per series or per row.
  - avoid: Turning markEvery off on a long stack — without the every-fifth cue the reader counts one by one, which is exactly the cost this mark was chosen to avoid.
