# apps/diagram — plan v1

Date: 2026-09-26 · Status: **decided** (§2 records the maintainer's answers; §10 lists what was taken as recommended and can still be overturned) · Companion: `2026-09-26-research.md` · Work packages: `../roadmap/README.md`

## 1. What this is

A test-and-demo web app, living entirely in `apps/diagram`, that draws **system architecture diagrams from a YAML definition** on the brand-ui flow canvas. It targets SaaS and hybrid landscapes — AWS, Azure, Google Cloud, Qlik, Databricks, Snowflake, ClickHouse, Salesforce, SAP, Oracle, Kubernetes, on-premises — with data movement, security/access, and the visual separation of _who runs what_ (customer-managed / SaaS / hosted / partner).

It is a **proving ground**: every custom node, zone, edge and the YAML dialect are built here first, against real diagrams, and the parts that prove generic are then moved into `@elabs-ai/components-flow` (and `icons`, `editor`, `ui` where they belong). The 2026-09-25 flow review (`docs/review/2026-09-25-flow-unified-contract-and-yaml-review.md`) already designed the library-side contract (FlowSpec v1, `defineFlowNodeType`, `createFlowRegistry`, `/spec` subpath, `FlowSpecCanvas`, `FlowNodeInspector`). This app is the domain layer that contract was missing, and its acceptance test.

### Ground rules (maintainer)

- Not deployed, not part of the standard gates. Plans, roadmap and research live **inside** `apps/diagram/`.
- **Only library components, templates and registry blocks.** Anything missing is built in the library, not in the app — except the app's own custom node components, which are exactly what a consumer is supposed to write (the `Flow/Custom Nodes` contract). When a custom node needs a primitive the library lacks, the primitive goes into the library.
- Library additions follow the house rules: tokens only, `cva` for visual axes, one-way dep graph, stories, `audit --strict`, no vendor-specific code in the library.
- Nothing is "done" until it has been driven in a real browser.

## 4. The YAML dialect (v0)

Goals: readable by a presales person in a text editor; trivially generatable by an LLM from a prose description (flat where possible, defaults everywhere, forgiving); every construct maps 1:1 onto FlowSpec; nothing in it is code.

```yaml
# yaml-language-server: $schema=./schema/arch-diagram.v0.schema.json
diagram: "0"
title: Qlik Cloud (SaaS) with a customer-hosted Data Gateway and on-premises sources
direction: LR # LR | TB — the ELK direction
nodeStyle: icon # icon | card — default node variant (D5)
theme: qlik # optional brand theme family for the canvas
legend: auto # auto | none | [owners, providers, edges]

zones:
  - id: customer
    owner: customer # customer | saas | hosted | partner  → boundary style + legend
    title: Customer managed
    children:
      - id: dc
        kind: on-prem # cloud-account | region | vnet | subnet | cluster | on-prem | datacenter | trust-boundary | generic
        title: On-premises data center (Vienna)
        children:
          - id: erp
            icon: sap/s4hana
            title: SAP S/4HANA
            subtitle: ERP
          - id: mssql
            type: datastore
            icon: microsoft/sql-server
            title: SQL Server 2022
            badges: [pii]
      - id: azure
        kind: cloud-account
        provider: azure
        title: Azure subscription (customer)
        children:
          - id: gateway
            icon: qlik/data-gateway
            title: Qlik Data Gateway – Direct Access
            subtitle: VM, outbound only
      - id: users
        type: actor
        icon: lucide/users
        title: Business users
  - id: qlik
    owner: saas
    provider: qlik
    title: Qlik Cloud (EU region)
    children:
      - id: qca
        icon: qlik/cloud
        title: Qlik Cloud Analytics
      - id: qtdi
        icon: qlik/talend-cloud
        title: Qlik Talend Data Integration
  - id: snowflake
    owner: saas
    provider: snowflake
    title: Snowflake
    children:
      - id: wh
        type: datastore
        icon: snowflake/warehouse
        title: ANALYTICS_WH

flows: # string shorthand or object form
  - erp -> gateway: CDC
  - mssql -> gateway
  - gateway -> qtdi:
      { label: Outbound only, protocol: HTTPS 443, secure: tls, kind: data, animated: true }
  - qtdi -> wh: { label: Load & transform, kind: data, schedule: hourly }
  - wh -> qca: { label: Direct Query / reload, kind: data, style: dashed, protocol: JDBC }
  - users -> qca: { label: SSO via Entra ID, kind: access, secure: sso }
  - qca <-> qtdi: { label: Catalog sync, kind: control, step: 3 }

styles: # reusable classes, applied via `class:` on nodes / zones / flows
  pii: { tone: warning, badge: PII }

notes:
  - at: gateway
    text: No inbound ports; the gateway dials out to Qlik Cloud.
```

Vocabulary:

- **Node `type`**: `service` (default), `actor`, `datastore`, `queue`, `external` (outside all zones), `note`. **Variant** `icon` | `card` per node, default from `nodeStyle`. Fields: `title`, `subtitle`, `icon`, `badges[]`, `class[]`, `tone`, `href`, `description` (hover/inspector only).
- **Zone**: `kind` × `owner` × `provider`; `collapsed`; `direction` override; `children[]` (or `parent:` on the child).
- **Flow**: `from`/`to` (node or zone id), arrow from the shorthand (`->`, `<-`, `<->`), `label`, `kind` = `data | request | access | control | network`, `style` = `solid | dashed | dotted`, `animated`, `secure` = `tls | vpn | private-link | sso | none`, `protocol`, `schedule`, `step`, `class[]`.
- **Sugar**: `a -> b: label` ≡ `{ from: a, to: b, label }`; `children:` ≡ `parent:`.
- **Positions**: only under `layout: manual`; the schema forbids `position` otherwise, so auto and manual never mix silently.
- **Schema**: a JSON Schema is generated from the dialect's definitions (the `ui` definition base's generator once flow adopts it; hand-written in P2 if needed) and referenced via `$schema` for editor tooling.

## 5. The catalog to prebuild

Nodes: `ServiceNode` (icon/card), `ActorNode`, `DatastoreNode`, `QueueNode`, `ExternalNode`, `NoteNode`, `ZoneNode`.
Edges: `DataFlowEdge` (all D12 axes, drawn through `FlowEdgePath`, label pill + protocol/schedule badges + step marker); floating variant for zone endpoints.
Chrome: spec-driven legend, title block, minimap, zoom, inspector, issues panel, examples gallery, export menu, theme switch.
Icon packs (app-only): per D4; naming `vendor/name`, with a generated index (`public/icons/index.json`) so the YAML validator can flag unknown icon names.

## 6. App UX

- Frame: **the dashboard app shell** (maintainer decision 2026-09-26) — the `dashboard` archetype template (`packages/cli/templates/dashboard.tsx`, generated from the `Templates/Dashboard` story: `SidebarProvider` + `Sidebar` + `SidebarInset` from `ui`), with the sidebar carrying examples, icon packs and settings; the inset holds the editor/canvas split. Left: Monaco YAML (`CodeEditor`). Right: canvas. Bottom of the editor: issues list, click → line. Top bar: examples, direction, node style, theme, layout mode, export.
- Canvas edits write back to YAML. The first drag under `layout: auto` prompts "Switch to manual layout?" (P3).
- Share = URL hash with compressed YAML; load/save `.yaml` files. No backend.
- Keyboard and a11y follow the flow package's contract (proxied focus, tone second channel, `Legend` for colour meaning).

## 8. Non-goals (v0)

Isometric rendering · multiple perspectives/views over one model (kept possible) · live agent-in-chat generation (A2UI; deferred as in the review) · palette/drag-drop as the primary authoring mode · import from draw.io/Mermaid/D2 · a backend · volume/weight edges.

## 9. Risks

- **ELK output quality on real diagrams** (dense zones, cross-boundary edges). Mitigation: per-zone direction, `pinBackbone`, and manual layout as the escape hatch (P3).
- **`FlowSmartEdge` avoidance at architecture scale** is unproven; compare against `@tisoap/react-flow-smart-edge` in P2 and file a library item if it falls short.
- **`pnpm check` rules** may still scan `apps/diagram/**` even with off-CI scripts. Verify in P0; add an explicit exclude if a rule trips.
- **Icon licensing**: by maintainer ruling the app may use any brand asset; `THIRD_PARTY_ICONS.md` only records where each pack came from (for refreshes), it is not a licence file, and nothing from it goes into `ATTRIBUTION.md`. The one hard rule stays: `public/icons` never reaches a publishable path.
- **Write-back fidelity**: round-tripping YAML must preserve comments and key order — use the `yaml` package's document API, never re-serialize from a plain object.

## 10. Taken as recommended (say so if you disagree)

- CI isolation by script names only (D14); explicit `check` excludes only if a rule trips.
- Export: PNG + SVG + vector clipboard; no PDF, no draw.io/Mermaid export in v0.
- No multiple perspectives in v0.
- Brand theme families are selectable (`theme:`), default theme by default.
- Persistence: files + URL hash, no backend.
- The dialect is optimized for LLM generation (flat, defaults, forgiving).
- Annotations in v0: notes, numbered steps, title block, legend.
- Dialect name: "brand-ui architecture diagram" (root key `diagram`), app title "Diagram".
- App-local custom node components are allowed; every primitive they need comes from the library.

## 11. Decided during execution (maintainer, 2026-09-26)

Asked by the orchestrator while hardening DG-09; each was answered with the recommended option.

- **Top-level `nodes:`** — a root `nodes:` list holds items that sit outside every zone (external systems, end users), next to `zones:`.
- **Reverse arrows** — `a <- b` keeps the written order (`from: a, to: b`) and only flips the arrowhead (`direction: back`); layout follows the text order.
- **Zone owner inheritance** — a nested zone without `owner:` inherits its enclosing zone's owner (resolved at compile time, DG-10); only a top-level zone without an owner gets a warning.
- **Fourth example (DG-13)** — added: Qlik Cloud as a SaaS zone, with only the customer-hosted Data Gateway VM inside the customer's cloud subscription (D13's framing).
