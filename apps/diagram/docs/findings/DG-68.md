## What changed

1. **Breadcrumb = location** (`shell/top-bar.tsx`, `TitleCrumbs`). The last crumb, the page's
   one `h1`, is the file name with its extension in the meta tone (`FileNameCrumb`), after the
   folders as plain text: `examples › qlik-cloud-data-gateway.yaml`. It never shows the
   diagram's title. A document without a workspace path names its location instead: "Shared
   link" for a `#doc=` link, "Not in the workspace" otherwise (review round 1).
2. **Tab = title** (`shell/doc-tabs.tsx`, unchanged). It already showed `doc.title`, truncated
   at `max-w-56`, with `title="<title>\n<path>"` for the tooltip.
3. **Title block** (`chrome/title-block.tsx`). `Heading size="display"` became `size="title"`
   (level 2). The description renders under it at prose measure (`text-pretty`), then the
   meta line. It is still the only place the full title reads, and it still exports with the
   picture.
4. **Dialect v0 accepts a top-level `description`.** The item assumed it did; it did not
   (`ROOT_DEF` had no such field, so the key was an `unknown-prop` warning). Added to
   `definitions.ts`, `types.ts`, `normalize.ts`, `compile-arch.ts`, `flow-spec/types.ts`,
   `from-react-flow.ts` (follow-up), `canvas-pane.tsx`; `schema/arch-diagram.v0.schema.json`
   regenerated; a row in `docs/dialect-v0.md` §2; exercised by `__fixtures__/valid-full.yaml`.
   `layout-edits.ts` (follow-up) places an inserted `layout: manual` after `description:`, not
   between `title:` and `description:`.
5. **Home stub** (`app.tsx`). The hint reads "Open a diagram from the Workspace in the
   sidebar." — the ⌘K palette is DG-29, out of R1.
6. **Six one-sentence descriptions**, as shipped:
   - `examples/clickhouse-cloud-stack.yaml`: “How one order’s change event travels from
     Postgres through Confluent Cloud CDC into ClickHouse Cloud and out to a dashboard.”
   - `examples/lakehouse-aws.yaml`: “How raw data lands in S3, is cataloged by Glue and
     processed by Databricks jobs into Snowflake, then queried by Qlik Cloud.”
   - `examples/qlik-cloud-data-gateway.yaml`: “How a customer-hosted Data Gateway reaches
     on-premises sources and lands change data in Snowflake without opening an inbound port.”
   - `examples/qlik-sense-enterprise-onprem.yaml`: “How users reach a three-node Qlik Sense
     site through the DMZ, and the storage, directory and license check it depends on.”
   - `templates/qlik-cloud-customer-landscape.yaml`: “How the customer’s data center reaches
     the Qlik Cloud tenant through a Data Gateway in Azure, and Salesforce feeds it directly.”
   - `templates/qlik-talend-cloud-pipeline.yaml`: “How Qlik Replicate moves on-premises change
     data into S3 and the Open Lakehouse cluster turns it into Iceberg tables.”

   The item asked for “what the picture shows, for whom”. The first build added an audience
   tail (“…, for a solutions architect scoping Qlik Cloud”); it made every description wrap to
   3 lines and the title block taller than before DG-68 (75 → 131 px), so review round 0
   dropped the tail. The two templates render once DG-26 reads dialect 1.
