## What changed

1. **Breadcrumb (`shell/top-bar.tsx`, `TitleCrumbs`)** — the last crumb used to be the
   diagram's own `title:`, duplicating the tab and the canvas title block. It is now the file
   name (`path.split("/").pop()`), with the extension in a `text-meta text-muted-foreground`
   span (`FileNameCrumb`). It stays the page's one `<h1>`. `fileTitle` (which stripped the
   extension) is no longer imported here — the breadcrumb wants the extension now.
2. **Tab (`shell/doc-tabs.tsx`)** — unchanged. It already showed `doc.title` (truncated,
   `max-w-56`) with `title={`${doc.title}\n${doc.path}`}` for the tooltip. Verified, not
   touched, per the item's own step 2.
3. **Title block (`chrome/title-block.tsx`)** — `Heading size="display"` → `size="title"`.
   Still the only place the full title reads; still exported with the picture (D9, unchanged
   export path). Doc comments at the old L23/L38 (now shifted) updated to say `title`, not
   `display`.
4. **Dialect v0 gains a top-level `description`** — this was the one real gap against the
   item's own claim ("dialect v0 already accepts it"). It didn't: `ROOT_DEF` (`spec/dialect/
definitions.ts`) had no `description` field, so a `description:` key in a workspace YAML
   was silently flagged `unknown-prop` (a warning, not blocking) and never reached the AST.
   Added the field to `ROOT_DEF`/`RootInput` (`definitions.ts`), `ArchDiagram`
   (`types.ts`), `normalize()`'s root read (`normalize.ts`), `FlowSpec` (`flow-spec/
types.ts`) and `compile-arch.ts`'s AST → FlowSpec step, then wired `canvas-pane.tsx`'s
   `<TitleBlock description={spec.description}>` and regenerated `schema/
arch-diagram.v0.schema.json` via `pnpm schema:build`. Confirmed in the edit-mode
   screenshots: the Problems panel reads "No problems" with a `description:` key present.
5. **Home stub (`app.tsx`)** — `homeHint` dropped its `⌘K` clause (DG-29, out of R1) and its
   `(keys: string) =>` signature; the call site no longer needs `shortcutText`/`SHORTCUTS`
   from `keymap.ts` for this string (both are still imported/used elsewhere in the file where
   needed).
6. **Six YAML files got a one-sentence `description:`** — the four `workspace/examples/*.yaml`
   (dialect 0, renders today) and the two `workspace/templates/*.yaml` (dialect 1, DG-26 not
   landed — the key carries over unchanged, inert until then). Each sentence: what the picture
   shows, for whom, drawn from the file's own header comment / content:
   - `clickhouse-cloud-stack.yaml`: "How one order's change event travels from Postgres
     through Confluent Cloud CDC into ClickHouse Cloud and out to a dashboard, for an
     engineer scoping real-time analytics."
   - `lakehouse-aws.yaml`: "How raw data lands in S3, is cataloged by Glue and processed by
     Databricks jobs into Snowflake, then queried live from Qlik Cloud, for a data engineer
     scoping an AWS lakehouse."
   - `qlik-cloud-data-gateway.yaml`: "How a customer-hosted Data Gateway reaches on-premises
     sources and lands change data in Snowflake without opening an inbound port, for a
     solutions architect scoping Qlik Cloud."
   - `qlik-sense-enterprise-onprem.yaml`: "How a DMZ reverse proxy, a shared repository and
     file share, Active Directory and a licensing check fit together, for an infrastructure
     team planning an on-prem Qlik Sense site."
   - `templates/qlik-cloud-customer-landscape.yaml`: "How a customer's data-center and Azure
     systems connect to the Qlik Cloud tenant through the Data Gateway, for a solutions
     engineer starting a customer-specific landscape."
   - `templates/qlik-talend-cloud-pipeline.yaml`: "How Qlik Replicate moves on-premises change
     data into S3 and the Open Lakehouse cluster turns it into Iceberg tables for downstream
     warehouses, for a data engineer standing up the pipeline."

## Review round (fix-r0)

Applying an independent verifier's and a `brand-ui-reviewer`'s findings against the build above.
Two of the four reported findings were duplicates across the two reviews (same root cause, filed
twice); addressed once each.

1. **F1 — breadcrumb said "Untitled diagram" for a path-less doc that has a real title (share
   link, import).** `TitleCrumbs` fell back to `TOP_BAR_LABELS.untitled` whenever `route.path ??
shownPath` was empty, even though the drawn AST's `title:` was known and shown one line below
   in the title block. Fixed in `shell/top-bar.tsx`: the path-less branch now reads
   `drawnTitle || TOP_BAR_LABELS.untitled` (`drawnTitle = useDiagram((s) =>
s.drawn.ast?.title?.trim())`), so "Untitled diagram" now only shows when the diagram really
   has no title either. Reproduced the review's own repro (a `#doc=<deflated-yaml>` share link
   for `lakehouse-aws.yaml`, no path): before, `h1`/breadcrumb read `"Untitled diagram"` against
   a title block reading `"Lakehouse on AWS with Databricks and Snowflake"`; after, both read the
   same title. Evidence: `fix-r0/52-after-share-link.png`, `fix-r0/52-after-share-link.json`.
2. **F2 — dialect v0 reference doc did not list `description`.** The root `description` field
   was real in code (`ROOT_DEF`, `types.ts`, `normalize.ts`, schema) since the build above, but
   `docs/dialect-v0.md` §2's table did not have a row for it, and the kitchen-sink fixture
   (`__fixtures__/valid-full.yaml`) did not exercise the key, so `#dev/spec-check` never touched
   it. Fixed: added a `description` row to §2 (between `title` and `direction`, matching field
   order) and a `description:` line to `valid-full.yaml` right after `title:` — the fixture's
   own `# expect: none` is unchanged (the field is fully supported, adds no issue). Evidence:
   `fix-r0/13-prettier-check.log` (doc reformatted clean), diff in the branch's own history.
3. **F1/F-sizing — the title block grew, not shrank, on 3 of 4 examples (75px → 131px).** The
   169–189-character descriptions (each including a "for `<audience>`" tail) wrapped to 3 lines
   at `max-w-prose`, and `qlik-sense-enterprise-onprem`'s fit zoom dropped 0.444 → 0.416. Fixed
   by trimming all six `description:` values to one sentence without the audience tail
   (105–130 characters each — see the diff for exact wording) and adding `text-pretty` to the
   description `Text` in `title-block.tsx` (belt-and-suspenders against an orphan last word).
   Re-measured at 1440×900, light, view mode (`fix-r0/measure-fix.json`, script
   `scratchpad/measure-fix.mjs`, not committed):

   | example                      | before (branch)            | after (fix-r0)                 | base (no description) |
   | ---------------------------- | -------------------------- | ------------------------------ | --------------------- |
   | qlik-cloud-data-gateway      | 131px, 2 desc lines→3\*    | **111px, 2 lines**             | 111px (2-line title)  |
   | clickhouse-cloud-stack       | 131px, 3 lines             | **111px, 2 lines**             | 75px                  |
   | lakehouse-aws                | 131px, 3 lines             | **111px, 2 lines**             | 75px                  |
   | qlik-sense-enterprise-onprem | 131px, 3 lines, zoom 0.416 | **111px, 2 lines, zoom 0.429** | 75px, zoom 0.444      |

   \* `qlik-cloud-data-gateway`'s base was already 111px pre-DG-68 (its title alone wraps to 2
   lines at that card width), so its own before/after delta is smaller than the other three.

   The block is now uniformly 2 description lines everywhere (down from 3), a 20px/line
   reduction (131→111). It is not back to the description-free 75px baseline — a real
   one-sentence description at prose measure is inherently taller than no description — but it
   no longer scales with the audience-tail length, and the fit-zoom regression on the tightest
   example is mostly recovered (0.416 → 0.429 of the base 0.444). Screenshots:
   `fix-r0/32-after-light-1440-<example>-full.png` (all four, light), `fix-r0/33-after-dark-
1440-qlik-cloud-data-gateway.png` (dark, contrast check), `fix-r0/31-after-light-lakehouse-
aws.png` (full-page, includes the breadcrumb/tab/title-block trio in one shot).
