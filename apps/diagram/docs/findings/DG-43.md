# DG-43 — Offline interactive publishing

Export → **Interactive HTML** creates one `.atlas.html` file. It uses the shared technical and visual canvases, lens transition, details cards, component inspection, stories, legend and flow particles. It starts with the authored technical drawing; transient camera, direction and expansion choices are not published. The publishing theme and resolved style profiles are fixed in the file.

## Privacy and capability boundary

The exporter builds a versioned, validated snapshot of the reachable diagram references, catalog entries and used icon assets. Notes and metrics are excluded recursively before compilation and serialization, including catalog-inherited note nodes. Dormant note text is excluded even when a node overrides its inherited type. Public descriptions and story captions remain. A required flow, story or reference to removed content fails publication clearly instead of producing a partial diagram. Comments and authoring-only fields are not included.

The viewer validates the envelope, sanitized content, reference closure and canonical profile data again, then freezes it. Build-only adapters supply immutable embedded data and no authoring services. The viewer does not mount the editor, workspace management, autosave or live reload. Its central text mutation boundary is read-only. Embedded sources use anonymous component paths rather than original workspace paths.

JavaScript, CSS, fonts and used icons are inline. A script-hash CSP disables connections and external resources; JSON escapes script-closing text. Public documentation links remain explicit navigation. The file is not encrypted: its retained public diagram content is readable to recipients. Review that content before sharing.

## Build and size

`build:local` produces the viewer template before the normal application build. Development generates that production template lazily on the first publish request. Publication verifies that the root, referenced files, catalog and style configuration did not change during preparation; an inconsistent snapshot is refused and can be retried.

The acceptance budget is 3 MiB gzip. The three shipped showcase diagrams and an adversarial nested fixture remain below this budget (largest: 5,451,636 raw bytes, 2,035,529 gzip bytes); the durable browser check records both raw and gzip bytes for every artifact. Raw HTML is larger because it includes the shared rendering runtime. No folder publishing, hosted viewer, iframe API or MCP publishing tool is included in R1.

## Observer repair

WebKit exposed a native ResizeObserver delivery loop in React Flow's node observer in the production offline viewer. Deferring only that observer removed the warning; waiting for fonts and batching app-level controlled dimensions did not. The repository's pnpm patch coalesces node measurements into one animation-frame update, drops disconnected or reassigned elements, and cancels queued work on unmount. Tests execute both installed ESM implementations. The patch applies to this repository's ESM/browser build; it does not claim an upstream release or repair of the package's UMD distribution.

## Verification

- 466 local Node checks, including nine snapshot/privacy/profile cases and eight installed-observer lifecycle cases.
- Actual menu downloads: four diagrams × three browser engines × desktop/phone, including all three shipped showcase styles. Authoring and offline visual paint are compared. Sources remain unchanged; no writes, external requests or browser errors occur.
- Six normal-motion control cases cover particles, keyboard pause/resume, live reduced motion, details, story/presentation, drill-down and read-only interaction. Nine tampered files are refused across the three engines.
- Independent review covers inherited-note privacy, profile tampering, CSP hashes, offline controls and accessibility. Snapshot checks deliberately fail unsupported versions, remote icons and unfiltered private content.
- Existing navigation (22 checks), composite (four theme/width cases), story (16 groups plus normal motion) and view-mode (11 checks) regressions pass. This caught a pre-existing phone story-readiness race, also reproduced without the observer patch: readiness now verifies actual rendered node geometry before playback advances.
- Local typecheck, lint, production build and strict style audit pass. Lint retains eleven pre-existing warnings.
