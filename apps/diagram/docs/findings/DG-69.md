# DG-69 — generic catalog products and live vendor creation

Completed the bounded generic-entry stream. `catalog_update` accepts new product slugs
with a valid kind, an optional known icon, and explicit `create_vendor: true` for a new
vendor. Invalid batches create no file. Curated maps and curated flags remain protected,
including YAML aliases; parts cannot be shadowed by the writer. Generic entries store
`generic: true` and remain in `catalog_missing` only while description or docs are missing.

The server and bundled browser merge return the same effective drawable icon. A matching
pack icon wins; otherwise an explicit known icon wins, then the kind glyph. New diagrams
use `ref: catalog/vendor/slug`. Legacy `icon: vendor/slug` resolves before validation and
compilation without rewriting the source. A hand-edited unknown icon reports a catalog
problem and keeps the product with its kind glyph. `note` uses the already available
`lucide/file` glyph; no library change or new icon dependency was needed.

## Root causes closed

- New vendor files changed the eager catalog import glob. Vite's import-glob plugin ran
  after the ordinary workspace plugin and could add module updates after the workspace
  hook returned an empty list. This reloaded the page or left multiple diagram-store
  modules alive. The workspace plugin now runs after the import-glob plugin, while its
  data-file filter still leaves ordinary source HMR alone. SSE refreshes catalog data.
- On a phone, a long reference makes the entry's YAML snippet scroll horizontally. The
  snippet is now a labeled keyboard-focusable region with visible focus, and real Arrow
  Right scrolling is tested.
- Generic slugs can contain punctuation. The missing-worklist sort now uses the same
  string ordering as its cursor, so pagination cannot skip a product.

## Reproduction and proof

A representative MCP request (the durable browser test sends the same shape with a unique
fixture vendor and records every request/response in `results.json`):

```sh
curl -sS http://localhost:5424/mcp \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"catalog_update","arguments":{"vendor":"example-vendor","create_vendor":true,"entries":[{"slug":"analytics","name":"Generic analytics","description":"Analytics without a product icon.","docs":"","kind":"datastore"}]}}}'
```

The result lists `analytics` in `written`. Omitting `create_vendor` for an unknown vendor
returns an error; setting `icon: fake/icon` returns a rejected entry and creates no vendor
file. A second valid call can use `icon: lucide/brain` without the creation flag.
