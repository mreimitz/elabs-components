# Style profiles

The runtime ships two profiles: `atlas-clean` for technical drawings and `qlik-marketecture`
for visual drawings. Diagram `style.technical` and `style.visual` select the matching profile
or `inherit`; root `styles` remains the independent technical class map.

Each lens resolves theme defaults, then `workspace/atlas.config.yaml` `styles`, then diagram
`style`. An omitted choice or `inherit` keeps the preceding choice. The resolved snapshot
includes provenance, profile data and theme-bound hero identity; these are suitable for a
standalone viewer without reading workspace files.

Qlik themes bind hero to `qlik` and use the fixed visual palette. Other themes bind hero to
`null` and retain semantic owner styling through the same visual profile with effective
`ground.followTheme: true`. Workspace and diagram YAML cannot override hero identity.
The Qlik profile is an approximate drawing reference, not a claim of verified vendor fidelity.
Its darker hero fill supports white text; the brighter green remains a zone accent.

Profile loading is pure and bounded: at most 32 sources, 64,000 characters per source and
8 inheritance levels. Only known fields, paint values and anatomy are accepted. Inheritance
must remain within one lens; objects merge and arrays replace. The runtime does not discover
custom workspace profiles. Malformed YAML, duplicate keys, excessive aliases, cycles, unsafe
CSS values and invalid resulting profiles produce issues rather than partially applied data.

Workspace configuration supports only `styles`. It shares the existing workspace event
stream, refreshes after reconnect, rejects obsolete async reads and preserves last-good data
with issues after malformed updates. Deletion resets defaults. The configuration file is
excluded from the diagram tree. No configuration editor or browser write API is introduced.

Coverage: pure profile/cascade/config races, diagram schema and positioned compiler errors,
real MCP validation/create refusal, and renderer/config integration browser checks. Rendering
and lifecycle evidence are recorded with the integration run. Folder overrides, extra
anatomies, custom profile authoring and additional profile families are outside this release.

Independent review closed four findings: malformed hex colors and prototype-named fields are rejected; fixed-profile chrome supplies its own elevated surface/minimap paint; changing theme during a morph cancels the captured transition before new paint. Ordinary forward, backward and mid-flight reversals still use the continuous shared camera. Customer-safe publishing captures this same effective profile snapshot in DG-43.

Verification: 448 Node checks, 6 actual MCP checks, four-theme browser/config/morph checks, nine three-showcase SVG/PNG exports, typecheck/build/strict audit and 98 repository conventions/17 generated-artifact checks pass. Lint has zero errors and 11 existing warnings. Browser runs report no page errors or workspace writes; config reload uses one event stream. Profile fidelity remains approximate.
