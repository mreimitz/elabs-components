# Authored visual layouts

A `visual` block supplies partial structure over the technical diagram. Explicit boxes claim their members; remaining nodes derive using the existing parent/vendor grouping. A catalog capability, when supplied, is a stronger grouping signal. No product metadata is guessed. Zone roles override inherited ownership/provider heuristics.

Lane IDs are independent of lane roles. `of` assigns a zone's descendants, with the nearest authored zone assignment winning. `controlPlane` lifts the member's existing box into the upper band; it never duplicates content. `sub` is a subset of the same box's technical member IDs. A hidden member cannot also be explicitly assigned to a box. Notes remain technical annotations.

Qualified members resolve through workspace references, never through catalog leaves. Referenced diagrams with an authored visual block inherit namespaced lanes and boxes; parent explicit membership wins. Explicit qualified membership or hiding also requests a finer child view, so unclaimed children remain visible. Traversal is bounded to eight reference levels and 1,000 imported members. Repeated shared dependencies cannot multiply indefinitely; exceeding the limit emits a positioned error and keeps that reference coarse rather than publishing a partial child layout.

Flow aggregation preserves independent data and non-data channels and their directions. Opposite flows merge only within the same channel. Flow overrides add label/process metadata to an existing unordered box pair without changing its traffic directions; a pair with no technical aggregate is rejected with a positioned error. Unrelated aggregates remain. Directed cycles are valid. Duplicate overrides of the same pair are invalid.

The built-in process vocabulary is `landing`, `storage`, `mirror`, `transform`, `elt`, `replication` and `quality`. Catalog tags matching this vocabulary become process pills; authored processes replace that derivation, including an explicit empty list. A later style context can pass its vocabulary to the same resolver.

`resolveVisual` is pure and returns a lens plus validation issues. Browser and MCP validation use the same cross-reference checks. The pane and morph share the resolved snapshot through the app adapter.

`materializeVisual` produces a text change for the caller's ordinary edit transaction. It never saves, changes mode or modifies technical entities. It preserves bytes outside the visual value except when detaching aliases that referred to a replaced anchor; those consumers retain their original parsed values. Comments inside a replaced visual value are retained as comments. Output is reparsed and compared with every non-visual value before being returned. Malformed, excessively aliased, cyclic or otherwise unrepresentable YAML is refused with a reason. Equivalent materialization returns the original bytes. Applying or resetting an authored layout remains an explicit preview/confirm operation, available only in Edit mode.

Core regression coverage is in `scripts/tests/visual-core.test.mjs` and the capability cases in `scripts/tests/catalog-generic.test.mjs`. It covers shipped templates, source-positioned errors, parent precedence, inheritance limits, parallel direction semantics, comment/alias/CRLF/flow-map preservation, idempotence and live/bundled catalog parity.

The authoring controls preview changes before an isolated undo transaction and disable invalid or stale input. Named control-plane geometry, process pills and labeled routes share the morph snapshot. Browser checks cover both shipped templates in light/dark,58 actual IntelliSense cases,22 navigation cases and phone stale-preview/undo behavior. Core parent cycles, lane precedence, hidden/control contradictions and invented visual connections were corrected through independent review. Explicit boxes read their ownership from technical ancestors even when default grouping would fold a network aside.

Rapid previews exposed two Monaco lifetime faults. The shared DiffEditor now owns and cancels its view model before disposing text models. The repository additionally patches Monaco0.55.1 global hover/markdown factories to use root services, since a disposable diff child service could otherwise break a surviving editor. The dependency patch applies to this repository; the component changeset covers only its view-model lifecycle repair. A60-cycle browser regression checks both themes, surviving suggestions/hover and zero leaked models.
