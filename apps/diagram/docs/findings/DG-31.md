# DG-31 — story playback

The R1 implementation adds typed stories to the existing architecture dialect and uses the
same checker for editor and MCP writes. Explicit stories replace implicit flow-step groups;
empty steps disable playback. Flow targets preserve their direction and compiled identity,
including duplicate endpoint keys across expanded reference instances.

Playback owns temporary camera/highlight/expansion state. It never edits the source diagram,
adds undo entries or captures a story-framed thumbnail. User gestures relinquish camera
control. Source, document, lens and nested-inspection changes cancel obsolete playback.

## Boundaries

- Playback operates in the technical lens; the visual lens provides an explicit switch-and-play
  action. Visual story mapping remains with the later lens work.
- Play runs once. There is no kiosk loop or automatic startup. The existing autoplay boolean
  is retained with an informational diagnostic when true.
- Captions support paragraphs, bold/emphasis, inline code and safe links. Raw HTML and media
  syntax remain literal text. The full editor MarkdownPreview lacks a media-free renderer seam,
  so the app uses a small caption-specific React renderer with the shared typography primitives.
- Pure MCP live views stay inert. Presenter windows, recording/export controls and particles
  are outside this slice.

## Library seams

The app imports React Flow's `getViewportForBounds` and `ViewportPortal` directly because the
flow package does not re-export them. Camera animation stays app-owned so a generation change
or user gesture can cancel it deterministically. Existing contrast-preserving dimming keeps
labels at full opacity while muting non-target marks.

## Durable checks

- `story-dialect.test.mjs`: grammar bounds, positioned target errors, explicit/implicit behavior,
  direction and nested flow identity.
- `story-completions.test.mjs` and the editor browser suite: partial/quoted targets, safe buffer
  handling, schema completion and snippet tab stops.
- `story-runtime.test.mjs`: progress, source isolation, action boundaries and route state.
- `story-markdown.test.mjs`: real typography rendering, safe links and inert media/HTML.
- `story-interactions.mjs`: real camera, controls, temporary expansion and theme/phone checks.
- `story-room.mjs`: dynamic legend/navigation clearance at phone, tablet and desktop widths.
- `story-example.mjs`: recorded six-step ClickHouse story, real flow following and unchanged source bytes.

Review evidence and recordings are kept in the local `.evidence/roadmap-story/` handoff.

## Story controls layout follow-up (2026-09-29)

The start button and the active playback row now share the collapsed legend's bottom level
when the canvas has enough room. The title and description sit above the timeline, with
Previous/Play/Next grouped together in the bottom row. The caption keeps a fixed reading
height across steps; long descriptions and callouts remain available by scrolling. Changing
steps resets that scroll position. Keyboard scrolling stays within the caption, and Escape
ends the story and restores focus to its start button.

The measured collision layout still lifts the player above overlapping legend or navigation
panels on narrow canvases. Presentation's exit and flow-animation controls sit at the top-right,
leaving the bottom playback row clear. On narrow canvases the title sits below those controls;
on wider canvases its width leaves space beside them. The shared player keeps the same
behavior in published HTML.

`tests/story-controls.mjs` covers the six-step Talend story and short, long and missing
caption fixtures in light/dark at desktop/phone widths: bottom alignment, content order,
fixed dimensions, keyboard scrolling, focus return, presentation clearance and no document
writes. Existing story interaction and room regressions remain the keyboard/camera and
expanded-legend checks.
