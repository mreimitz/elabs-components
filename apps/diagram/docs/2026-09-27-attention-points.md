# Atlas — attention points (what could go wrong, and the guard for each)

Date: 2026-09-27 · Written after the platform decision (P1–P9). Ordered by when it bites.

| #   | Attention point                                      | Why it matters                                                                                                                                                                                                                                                                                                               | Guard                                                                                                                                                                                                                                           |
| --- | ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Scope: 58 items across five tracks**               | Everything is good, not everything is next. Without a cut, wave 3 balloons and nothing ships to a first user.                                                                                                                                                                                                                | Name a **"first shippable"**: waves 0–2 + DG-30/31 (particles, story) + DG-36–38 (lenses) + DG-43 (interactive HTML). Everything else waits for a real user's pull. Review the cut after wave 2.                                                |
| 2   | **The brands ruling does not survive deployment**    | "All brands free inside `apps/diagram`" was a local-demo ruling. A Qlik-hosted Atlas showing AWS/Azure/Snowflake icons to Qlik's users is _use in diagrams_ (allowed by every vendor) — but redistribution of the packs inside a product needs each vendor's terms re-read, and `ATTRIBUTION.md` may need entries after all. | Before DG-57: a per-pack terms review with the deployment lens (use vs redistribute), a `THIRD_PARTY_NOTICES` served by the deployment, and Amazon Ember / vendor fonts never bundled (Inter only).                                             |
| 3   | **Customer data inside diagrams**                    | Once shared, diagrams carry customer names, logos, landscapes — confidential and personal data under GDPR (Austria/EU deployments).                                                                                                                                                                                          | Data classification of documents (`confidential` default for customer folders), retention/trash policy, export controls, audit; a DPA-ready description of what the server stores; no analytics that leak document content.                     |
| 4   | **Dialect stability once shared**                    | v0→v1 was easy with one user. With hundreds of diagrams across users, a breaking dialect change is a migration event.                                                                                                                                                                                                        | Version every file (`diagram: "1"`), keep the upgrader, add a **compatibility rule**: within a major only additive keys; deprecations warn one release before removal; the MCP `spec.validate` reports deprecated usage.                        |
| 5   | **Prompt injection through shared content**          | Descriptions, notes and catalog text are markdown that LLM sessions read via MCP, and other users' diagrams are content. A malicious description could steer a Claude session that has write access.                                                                                                                         | Render markdown without raw HTML; the MCP skill tells the session that document text is data, not instructions; server-side write validation (protection, visibility) is the real guard — never rely on the model behaving.                     |
| 6   | **Performance at platform scale**                    | Particles, ELK on 200-node landscapes, a workspace with 2,000 diagrams, thumbnails for all of them, live reload fan-out.                                                                                                                                                                                                     | Budgets stated as numbers in items: ≤ 4 ms/frame particles, < 500 ms layout at 200 nodes, Home lists paged and indexed server-side, thumbnails rendered on save (not on list), SSE per document not per workspace.                              |
| 7   | **Testing a deployed product with an off-CI app**    | "Off the standard gates" was right for a demo; a product used by a vendor's presales team needs gates.                                                                                                                                                                                                                       | At DG-57: the app and server join a **separate CI workflow** (contract tests, local-mode smoke, browser tests on the three showcases) without touching the library's gates; keep the library rule that the app never leaks into `pnpm test`.    |
| 8   | **The library harvest gets crowded out**             | The original purpose was to enhance the flow package. The app now has 58 items; P4 (the harvest) has none scheduled.                                                                                                                                                                                                         | Keep DG-19's inventory alive: every wave adds its gaps; schedule the first harvest track (flow/architecture, flow/spec, export, group auto-fit) right after wave 2 — it also de-risks the app by moving generic code under the library's tests. |
| 9   | **Catalog quality from an LLM loop**                 | 670 descriptions and docs links written by a model, curated by one person: some will be wrong, and a wrong docs link in a customer deck is embarrassing.                                                                                                                                                                     | `curated: false` badge shown in the UI until reviewed; HEAD-checked links; a "report wrong description" action feeding the owner; vendor-by-vendor review sessions, hero vendor first.                                                          |
| 10  | **Name and identity**                                | "Atlas" collides with MongoDB Atlas, Atlassian, and others; a vendor deployment carries its own name anyway.                                                                                                                                                                                                                 | Treat "Atlas" as the working name; the deployment shows the vendor's product name (a deployment setting); check the name before anything public.                                                                                                |
| 11  | **Non-developers cannot run local mode**             | `pnpm dev` is a developer's tool; your own rule says end-user deliverables must work without a terminal on Windows and macOS.                                                                                                                                                                                                | Local mode stays for you; for everyone else the deployment is the product. If an offline single-user version is ever wanted, a packaged desktop build (Tauri) of the same app + local middleware is the path — note it, do not build it yet.    |
| 12  | **Accessibility and language for a shipped product** | A vendor-internal tool still faces procurement checklists (WCAG 2.1 AA) and DACH users.                                                                                                                                                                                                                                      | The library's rules already carry a11y; keep the greyscale/keyboard checks in every item; plan G11 (i18n) before external sharing (phase 2).                                                                                                    |

Also worth keeping in view: **operations** (backups of the Git store, restore drill, health/metrics, log hygiene), **who owns the catalog and profiles in a deployment** (an admin role and a review queue, DG-24/41), and **export fidelity** (fonts and marks must look identical in the app, the PNG, the PPTX and the published HTML — one rendering path, tested on the three showcases).
