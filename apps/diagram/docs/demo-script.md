# Atlas — the R1 demo in 12 steps

Run this tour against the integrated R1 build, using a disposable customer copy. It is the
maintainer's phase A acceptance tour: a successful automated run demonstrates the product
behavior below. Real-deal usefulness and written owner acceptance remain separate decisions.
Unaided colleague onboarding belongs to phase B.

Start the local app with `pnpm --filter @elabs-ai/diagram dev` and use the URL printed by the
server (normally `http://localhost:5180`). Choose a Qlik theme with normal motion, keep the
shipped templates and `components/qlik-cloud-tenant` in the workspace, and begin on Home.
Do not edit the source template. “Contoso” below is fictional test content.

| #   | Action                                                                                                                                                        | Expected behavior                                                                                                                                                                                                                                                                                                                                                            |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Open Home.                                                                                                                                                    | Recent diagrams, folders, components, **New diagram** and **New from template** are available. An empty recent list is valid in a fresh browser.                                                                                                                                                                                                                             |
| 2   | Choose **New from template**, then **Qlik Cloud and the customer landscape**.                                                                                 | A copy is created under `workspace/customers/` and opens in **Edit** mode in the technical lens. Its title ends in `(copy)` or the next numbered copy suffix. There is no naming dialog. The original template is unchanged; technical flows animate when motion is enabled.                                                                                                 |
| 3   | Choose **Done**, then hover **Qlik Data Gateway – Direct Access**.                                                                                            | The details card shows the gateway's title and description and a safe **Open docs** link. Moving away or pressing Escape dismisses it.                                                                                                                                                                                                                                       |
| 4   | Double-click the **Qlik Cloud tenant** composite. Inspect its contents, then press Escape.                                                                    | Read-only drill-down shows the referenced diagram and a breadcrumb. Escape restores the parent drawing and camera without changing either file.                                                                                                                                                                                                                              |
| 5   | Press `E`. In YAML, change the top-level `title` to `Contoso`.                                                                                                | The editor opens with the inspector closed; the diagram and tab title update. The copied file keeps its generated filename in `customers/`. Wait for **Saved** before continuing.                                                                                                                                                                                            |
| 6   | Select **SQL Server** (`erp`) and open **Inspector**. In its fields, set the title to `Contoso ERP (SAP)` and choose icon `sap/s4hana`.                       | The written overrides update YAML and the drawing. Other nodes retain their positions; the catalog item and source template are unchanged.                                                                                                                                                                                                                                   |
| 7   | Add a flow under `flows:`. Type `- erp -> `, choose `tenant.qtdi` from completion, and finish the line as `- erp -> tenant.qtdi: CDC`.                        | Completion includes the qualified inner endpoint with its title. The new edge reaches the tenant's named port while collapsed and its inner node when expanded. The YAML remains valid and saves.                                                                                                                                                                            |
| 8   | Choose **Done**, focus the canvas, and press `L`.                                                                                                             | The drawing morphs into the visual lens with authored lanes, capability boxes and process pills. The Qlik profile supplies the navy ground and vendor styling. Switching lenses leaves YAML unchanged.                                                                                                                                                                       |
| 9   | Choose **Play story in technical view**. The app switches lenses and starts playback. Advance to step 2 with **Next step** or `→` while the canvas has focus. | Story playback runs in the technical lens: step 1 frames its targets and shows its caption; step 2 follows the outbound gateway flow. Other content dims. Pause to inspect the step before presenting. Camera movement and temporary expansion do not write to YAML.                                                                                                         |
| 10  | Choose **Present story** or use `P` with canvas focus. Try `←`/`→`, then exit.                                                                                | Presentation removes the editor shell and preserves story navigation. This is an in-app presentation, not the browser's native full-screen mode. Escape first ends an active story; another Escape exits presentation, or use its exit button.                                                                                                                               |
| 11  | Open **Export** → **Interactive HTML**. The menu states that notes and metrics are excluded. Open the downloaded file with networking disabled.               | One self-contained `.atlas.html` file provides both lenses, story playback and safe details without the editor, workspace writes or external requests. There is no settings dialog: notes, metrics and private metadata are excluded. Invalid or missing required content refuses export with an error rather than producing a partial file. Export the fictional copy only. |
| 12  | Wait for **Saved**, close the browser tab, and reopen the local app with the same browser profile. Open **Contoso** from Recent.                              | The persisted customer copy reopens with the changed title, icon and flow. A thumbnail appears after capture; until then **No preview yet** is valid. Its YAML is on disk under `workspace/customers/`; the source template is still byte-for-byte unchanged.                                                                                                                |

A recording should show the actual UI actions, including the switch back to technical story
playback and the offline HTML. Record the tested commit, browser, theme, viewport and exact
result for every step. Keep console/network evidence and the original template hash beside
the recording. Retain only the disposable copy and artifacts needed for review; clean test
fixtures afterward. Do not describe a prepared or partially executed tour as passed.

The first interactive export may take about 30 seconds while the local viewer template builds.
Wait for the download or an explicit error; do not retry repeatedly.

Run the full tour once with normal motion on desktop. Recheck the viewer and critical controls
in both light and dark themes and at phone width; existing focused regression suites provide
the broader matrix. A recording supplements those assertions rather than replacing them.

Out of scope: catalog drag-and-drop, phase B shared-workspace onboarding, customer adoption
claims, and communications to customers. Owner acceptance should cite the completed tour and
state any remaining limitations explicitly.
