## Verification boundaries

The tour follows one normal-motion desktop path. Broader light/dark, phone, keyboard, read-only, reference, story and publish matrices are recorded in the linked findings and [test instructions](../testing.md). The publisher's final acceptance included 24 offline showcase cases and 15 control/tamper checks; its largest measured snapshot was 2,035,920 bytes gzip, below the 3 MiB budget. The final app suite recorded 466 passing Node tests. These are separate checks, not extra tour cases. The combined catalog build at `b9412487` also passed all 24 offline cases again, app typecheck/build, strict style audit, lint with zero errors and eleven inherited warnings, and all 98 repository rules. The 470 repository rule fixtures passed in the completion run. The changed-package runner executed no tasks because this private app intentionally uses direct local gates; it is not counted as app test coverage.

Additional local performance evidence is retained in the ignored evidence workspace: `roadmap-styles/motion` records neutral-theme lens transitions at 98.7–100% of frames within 16.9 ms; the companion `roadmap-styles/motion-qlik` run records 96.1–100% alongside reduced-motion stationary/early-open checks; `r1-completion/layout-200.json` records four actual ELK runs of a fixed-size 200-node/199-edge ternary tree at 42/30/37/30 ms. That is a bounded graph example, not a worst-case guarantee for all 200-node diagrams.

An earlier full-tour attempt showed a blank drill-down canvas beyond the five-second assertion timeout, with no browser exception or observed Vite reload. Its cause remains **unconfirmed**: a direct drill replay, an exact copy/hover/drill replay and subsequent complete workflow runs passed without a product change. A further ten fresh-browser repetitions on `b9412487` all passed the unchanged five-second assertion, with drill readiness at 522–535 ms, five inner nodes ready, successful Escape, unchanged source hashes and cleaned copies. There were no browser exceptions or external requests; the recorded HTTP 404s were expected reads of absent optional `atlas.config.yaml`. This strengthens the recheck without establishing a cause or claiming a product fix. The failure and replays remain under `apps/diagram/.evidence/r1-tour/` (`final`, `drill-probe.json`, `drill-copy-probe`). A later run passed steps 1–11 but exposed an ambiguous test locator for Contoso in both Recent and Folders; the harness now explicitly selects Recent. Another run was interrupted when its agent process ended and is not counted as a pass. Final accepted evidence is `final-complete/result.json`; earlier attempts are retained rather than relabeled.

That same 51-test file passed in isolation on both the branch and main; see [the recovery record](../findings/R1-recovery.md). Local build and focused gates do not establish remote CI status. The earlier `753a4dd5` [CI run passed](https://github.com/mreimitz/elabs-components/actions/runs/36496920431). CI for the final integrated closeout revision remains pending and must be checked separately.

## Reproduce

Use an isolated checkout with the shipped workspace fixtures, frozen dependencies, the current patches and a running local server. From `apps/diagram`:

```sh
DIAGRAM_URL=http://127.0.0.1:5446 R1_PACE_MS=6500 node tests/r1-demo-tour.mjs
```

`R1_PREFLIGHT=1` exercises steps 1–10 without accepted release artifacts. `R1_EVIDENCE` selects the diagnostic folder; `R1_RELEASE_DIR` selects the recordings and generated run result. Successful runs update `r1-tour-run.md` and `r1-tour-result.json`, leaving this handoff narrative intact. Review the result and recordings before declaring a new run accepted.
