# 11 · Decision record — agent-docs architecture (hub + spokes, generated, first-class llms.txt)

> **Status:** Accepted · 2026-06-06. Prompted by the bklit-charts comparison (does the rest of the
> library learn from its `llms-full.txt` + per-component skills?). This records the answer and points the
> existing working packages at it. It does **not** create a new stream — it sharpens **WP-03**, **WP-10**,
> and **WP-12**.

## Context (grounded)

- **What we have, centrally:** `brand-ui.manifest.json` (≈129 KB / 4,418 lines, generated by `@qlik-coe-emea/qlabs-components-cli`
  `pnpm manifest`) is the machine-readable anti-hallucination source; five **hand-written** skills
  (`brand-ui` hub, `brand-ui-component` routing, `brand-ui-audit` / `-registry` / `-theme`); and the
  **Storybook addon-mcp** as live ground truth — but only while `pnpm storybook` runs.
- **What bklit has that we don't:** a generated **`llms.txt` / `llms-full.txt`** (always-on, readable,
  server-independent) + per-component prose. brand-ui has **no `llms.txt` at all** (logged only as the
  optional gap E5).
- **The honest comparison:** bklit is ahead on _always-on readable prose_; brand-ui is ahead on
  _structure + live truth_ (a queryable manifest + real rendered props/tests via MCP that static text
  can't match and can't drift from). Neither dominates — they're different tiers.
- **The freshness reality:** `pnpm manifest` is **manual**; `scripts/build-skills.mjs` only **mirrors**
  the hand-written `skills/` tree to other harnesses (it does **not** generate skills from the manifest —
  so skills can silently drift); `check-package-registered.sh` only **warns**, and only that a _new
  package_ is named in `CLAUDE.md`. The reliable "regenerate + fail-on-stale" gate is **proposed**
  (WP-10 issue-01/03), not built.

## Decision

1. **Hub + spokes, generated from the manifest — not a monolith, not per-package-only.**
   - **Spokes:** each package emits its own slice — a generated `packages/<pkg>/llms.txt` (+ its manifest
     section) — co-located so it stays fresh and an agent working in one package loads only that surface.
   - **Hub:** one thin **root `llms.txt`** + the `brand-ui` hub skill that does **routing** ("which
     package for what") and **cross-package composition** (the one-way dep graph: `DataTable`→`@qlik-coe-emea/qlabs-components-data`,
     charts→`@qlik-coe-emea/qlabs-components-charts`, AI elements→`@qlik-coe-emea/qlabs-components-ai`, …). A map, not the territory.
   - Rejected: **monolith** (one giant file/skill — doesn't scale to 10 packages, burns agent context on
     irrelevant packages, single stale hotspot) and **per-package-only** (no routing — the agent can't
     tell where to start or how packages compose).

2. **`llms.txt` is first-class, not optional.** Promote it from gap E5 / "optional" to a **required,
   generated** artifact: per-package spokes + a root aggregate, emitted by the same `@qlik-coe-emea/qlabs-components-cli` generator
   that produces the context blocks. Borrow bklit's artifact; keep our freshness model (generated, not
   hand-written).

3. **Two tiers of agent truth, complementary not redundant.**
   - **Always-on (static):** the manifest JSON + the generated `llms.txt` + the generated `context`
     blocks in `CLAUDE.md`/`AGENTS.md`/`.cursor/rules`. Works at cold-start, in any IDE, for any agent
     (Claude, Cursor, Copilot, Gemini), **with no server running**.
   - **Live (dynamic):** the Storybook addon-mcp (and the future persistent `brand-ui` MCP) for real
     rendered props/stories/a11y when the dev server is up.
   - `llms.txt` is the cold-start tier _under_ the live MCP — not a replacement for it.

4. **Skills are generated-or-stale-checked, never purely hand-written.** Split each skill into a
   **generated catalogue region** (component/prop/token data, from the manifest, inside
   `<!-- brand-ui:gen:start -->`/`:end` markers) + **hand-written judgment prose** (when to use what,
   anti-patterns). The generated region is stale-gated like the manifest, so no skill silently lags the
   code; the prose stays human.

## Enforcement (the reliable hook the maintainer asked for)

Auto-regenerate + **CI `git diff --exit-code` stale-gate** over the manifest **and every derived
artifact** — `llms.txt` (per-package + root), the `context` blocks, the inventory regions, and the skill
catalogue regions — plus a pre-commit regenerate on the happy path. This is **WP-10 issue-01 + issue-03**;
it depends on **WP-01** (CI). Until it exists, "we keep the llm text + skill updated" is **manual and not
reliable** — that is the gap this record closes by making the artifacts generated and gated.

## Where it lands (no new stream)

- **WP-03 issue-04** (`brand-ui context` generator) → also emits **`llms.txt` per-package + root** (now
  first-class, not "optional").
- **WP-10 issue-03** (generate inventories + stale-check) → add the **`llms.txt` spokes/hub** and the
  **skill catalogue regions** to the generated-and-gated set.
- **WP-12** → the "which to use when" guidance (incl. the Lucide default, DP-01 issue-03) is part of the
  hub routing.
- **Per-package harvest, not one-off:** CH-01 issue-06 (charts docs) and DP-01 feed **their package's
  spoke**, not a special-case dump — every package's `llms.txt` is generated the same way.

## Consequence

A downstream agent **never hand-updates** inventory / `llms.txt` / skill catalogue: adding, removing, or
changing a component regenerates them, and the stale-gate blocks any drift. Adopting bklit's always-on
`llms.txt` this way gives its portability **without** its drift — the best of both.
