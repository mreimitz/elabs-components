# Salesforce Lightning Experience — visual spec for a CSS theme (as of Sept 2026)

Sources: `@salesforce-ux/design-system@2.264.1` ("Summer '26" release; SLDS 1 / `@salesforce/slds/legacy`), `@salesforce-ux/design-system-2@2.264.2` (SLDS 2 / Cosmos), Salesforce Help "Salesforce Cosmos Theme and SLDS 2 Availability", Trailhead modules, admin.salesforce.com release blogs (Winter '26, Summer '26). Packages unpacked in the review session's `refs/salesforce/pkg/` (not kept in the repo).

Provenance tags used below:

- **[token]** = read from `design-tokens/dist/ui-force.raw.json` or the compiled `assets/styles/salesforce-lightning-design-system.css` of the SLDS 1 package.
- **[sampled]** = pixel-sampled with PIL from a saved screenshot (GIF frames are palette-quantised, so ±2 per channel).
- **[observed]** = read visually from screenshots, not measured.
- **[assumed]** = reasonable inference, not verified.

---

## 0. Which look dominates in 2026 — decision

**Target the classic SLDS 1 "Lightning Blue" Lightning Experience.** That is still what the installed base sees and what people recognise as "Salesforce".

Evidence:

- Salesforce Help (_Salesforce Cosmos Theme and SLDS 2 Availability_): "As of Winter '26 [Oct 2025], SLDS 2 features are generally available (GA) in all Salesforce editions." and "SLDS 2 and Salesforce Cosmos are available for all **new** orgs and are turned on by default for these editions. They are also available for all **existing** orgs as an **opt-in**." No retirement date for SLDS 1 is published; "if Salesforce Cosmos isn't available, users continue to see the default UI that they're used to."
- Trailhead (_Plan Your Transition from SLDS 1 to SLDS 2_): activation is an admin action in Setup > Themes and Branding ("As soon as Salesforce Cosmos is activated … SLDS 2 is enabled for everyone in that org"). The built-in SLDS 1 theme is still called **Lightning Blue** and is the default in existing orgs.
- Winter '27 (Oct 2026) adds group-based (phased) activation of Cosmos, which confirms most existing orgs have not flipped yet.
- Salesforce's own admin-evangelist screenshots in 2025–2026 are mostly still SLDS 1 (list views, Flow Builder, Setup pages in the Winter '26 and Summer '26 posts); only the newest "Themes and Branding"/dashboard-branding GIFs show Cosmos.
- Practical pressure to move: dark mode requires an SLDS 2 theme.

So: existing/enterprise orgs = SLDS 1 look (this spec). Brand-new orgs and Developer Edition orgs created after Oct 2025 = Cosmos by default (see §13 for the differences, in case you want a toggle).

**Two corrections to the brief's assumptions:**

1. **Salesforce Sans is not the LEX font any more.** SLDS release 2.15.0 (25 Mar 2021, Spring '21): "Removed Salesforce Sans as the default typeface and replaced it with OS-specific defaults." Both SLDS 1 and SLDS 2 use a system-font stack. The npm package ships **no** font files at all (no woff/woff2/ttf; the only licence files are for images, icons and Sass). Token references to `/_slds/fonts/v2.3.0/SalesforceSans-*.woff2` remain in `force-font-commons` as legacy platform paths. Do not self-host Salesforce Sans; use the system stack. (2025 screenshots on macOS clearly render in SF Pro.)
2. **The global header is white, not blue.** The "blue-ish" impression comes from the **page background** in the Lightning Blue theme: a dark-blue textured band (mountains/clouds illustration, ~#1a5d9b–#2f6da9 sampled) directly below the nav bar, fading to a light blue/grey page. The header (logo, search, icons) and the app-nav bar are both white/near-white; only the 3 px line under the nav bar and the active-tab underline carry the app brand colour.

## 12. Other distinctive traits worth reproducing

- **Object icons**: 32/36 px rounded (4 px) coloured squares with a white glyph. [token]
- **Avatars**: 32 px, radius 4 px (square) or circle; grouped avatar bg `#107cad`. [token]
- **Dropdown menus**: white, `1px #e5e5e5`, radius 4 px, shadow `0 2px 3px 0 rgba(0,0,0,.16)`, 12 px items, padding `.25rem 0`, item padding `.5rem .75rem`, section headers uppercase 12 px `#444` ("MY FAVORITES"). [token]
- **Popover**: 20rem wide, white, `1px #e5e5e5`, radius 4 px, same shadow; footer `#f3f3f3`; walkthrough/feature variants filled `#0176D3` or `#001639`. Tooltip: `#001639`/`#032d60` bg, white 12 px text. [token]
- **Spacing scale**: 2 / 4 / 8 / 12 / 16 / 24 / 32 / 48 px (xxx-small → xx-large). [token]
- **Radii**: 2 px (small) / **4 px (medium — the system default)** / 8 px (large) / pill 15rem / circle. [token]
- **Borders**: 1 px thin, 2 px thick, 3 px (nav bar + active tab). Hairlines `#e5e5e5` inside components, `#c9c9c9` on component edges. [token]
- **Shadows**: card `0 2px 2px 0 rgba(0,0,0,.10)`, dropdown `0 2px 3px 0 rgba(0,0,0,.16)`, header `0 2px 4px rgba(0,0,0,.07)`, drag `0 2px 4px 0 rgba(0,0,0,.40)`, docked `0 -2px 2px 0 rgba(0,0,0,.16)`, inline-edit `0 2px 4px 4px rgba(0,0,0,.16)`. [token]
- **Utility bar** (bottom, console apps): fixed, 40 px, white, shadow `0 -2px 2px 0 rgba(0,0,0,.16)`; items 13 px `#181818` with icon. [token]
- **Docked composer / panels**: white, `1px #e5e5e5`, top radius 4 px. [token]
- **Split view** (Cases/Leads console): left list 12 px, rows `1px #c9c9c9` bottom, selected row white with left brand bar. [token]

## 13. SLDS 2 / Cosmos — what changes (for an optional "new look" toggle)

From `@salesforce-ux/design-system-2` `slds2.theme.cosmos.css` and Trailhead "Explore the New Salesforce UI":

- Brand: `--slds-r-color-brand-50: #066afe` (brighter blue); nine accent colour options; `light-dark()` dark-mode support built in.
- Font: still system stack (`system-ui, -apple-system, …`), but weights 100–700 available and a larger scale (`font-scale-1` 14 px, `-2` 16, `-3` 20, `-4` 24, `-5` 28); body copy reads 14 px.
- Radii: `radius-border-1..4` = 4 / 8 / 12 / 20 px (vs Lightning-Blue theme 2 / 4 / 8 / 16). **Buttons are pills** (`--slds-s-button-radius-border: pill`), bordered buttons have a dark `#5c5c5c` border and lift on hover (`translateY(-1.5px)` + hard 1.5 px shadow); brand buttons lift 2 px with a `#032d60` hard shadow; active state has an inset pressed shadow.
- Containers/cards: **radius 20 px (`radius-border-4`), no border, no shadow**, white on `#f3f3f3` surface-2; heading 20 px regular, navy `#03234d` (`on-surface-3`).
- Text: `on-surface-1 #5c5c5c`, `on-surface-2 #2e2e2e`, `on-surface-3 #03234d`; borders `#c9c9c9` / `#5c5c5c`.
- Shadows: layered (`shadow-1: 0 0 2px, 0 2px 2px, 0 -1px 2px` rgba(0,0,0,.18/.10)).
- Shell: white global header with a **pill-shaped search field**, app name + a **rounded-tab nav** with a blue underline; no dark-blue page band, pale `#f3f3f3` page; object icons become circles; highlights panel loses the grey box.
- Screenshot: `cosmos_account_record.jpg`, `cosmos_buttons.jpg`, `admin_report_dashboard_branding_f107.png`.
