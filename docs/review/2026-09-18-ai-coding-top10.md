## The ten

1. **Fix retrieval — it is the product.** Tokenise camelCase and multi-word queries, rank root components above parts above constants, reuse `SOURCE_ALIASES` as a synonym table, never return an empty answer (nearest match + "compose it from X+Y"). Give `chart-for` time/category/measure parsing so "by month by region" yields line/stacked-bar/small-multiples. Give the manifest a real `kind` taxonomy so counts agree everywhere.
2. **The live front door must never lag or lead the published packages.** Release the 23 pending changesets; deploy llms.txt/MCP/docs from the same commit as the npm publish; add a `release:smoke` step that executes every command printed in llms.txt and README against the published tarballs.
3. **Publish the benchmark.** `scripts/bench` exists, no run is committed. Run brand-ui vs shadcn vs MUI/Mantine on 2–3 models, publish the table on the homepage, re-run per release as a regression gate. Grow 5 greenfield tasks to 20+, and add _edit_ tasks (add a page to an existing app, keep it consistent) — that is the actual thesis of the library.
4. **Put the agent surface on a token budget.** `docs` defaults to a brief (import line, key props, one example, ≤1.5 KB) with `--full` on demand; MCP responses paginate; the main skill becomes a router under ~8 KB with references loaded on need; gate it (`pnpm check --rule agent-token-budget`).
5. **Make `create` provably green.** CI matrix: all six templates × (npm, pnpm) × (macOS, Windows) → install → build → tsc → `audit --strict`, against packed tarballs. Pin template deps to the CLI's version, code-split charts/motion, fix the peer warnings, print npm as well as pnpm next steps.
6. **Host the registry.** Today it is "self-hosted, `<your-host>`". Serve it at `elabs-ai.com/r/` with a shadcn namespace so `npx shadcn add @brand-ui/kpi-pace-01` works — the 65 blocks are the most differentiated asset and the hardest to obtain.
7. **Close the everyday gaps.** No exact-name match for: auth screens (login/signup/reset), CommandPalette, Toast, MultiSelect, TreeView, Kanban, Dropzone, OTPInput, Stepper, NotificationCenter, PricingTable. 40 of 65 registry blocks are KPI/infographic/agent-ops; none are auth, CRUD form/detail, empty/error/404 or onboarding. What an agent cannot find it hand-rolls — the inconsistency the library exists to prevent. (Some may exist under other names; then it is item 1.)
8. **Remove the "internal" positioning.** `package.json` description, PROJECT.md (incl. the non-goal "not a public, versioned library") and the llms.txt blurb still say internal apps / presales demos. Models and search read these strings.
9. **Ship a rendered verify loop, not only a static audit.** `brand-ui verify <url|dir> --json`: headless render, axe, console errors, one screenshot per theme family and mode, also as an MCP tool. `bench/score.mjs` already contains most of it. This is what lets an agent self-correct UI.
10. **Reach beyond greenfield Vite and beyond Claude Code.** `brand-ui init` for an existing app (Next.js App Router first, correct `"use client"` boundaries), a Next.js template, and emit Cursor/Copilot/Codex/Gemini rule files next to CLAUDE.md/AGENTS.md.

Order of work: 2 and 8 (hours) → 1, 4, 5 (days) → 3 (publishable proof) → 6, 9, 10, 7.

Not verified in this pass: the hosted MCP's tool output sizes, Windows behaviour, the other five templates, per-component example coverage in `docs` output.

Two defects the verification found, fixed in this change:

- **`npx @elabs-ai/components-cli mcp` answered "No manifest." everywhere outside this monorepo** — the stdio server only looked for a manifest when it found a repo root, so it never read the one packed with the CLI. Live in npm 4.2.0 today. `test/mcp.test.mjs` now starts the server from a packed-shape copy in a temp dir.
- **pnpm 11 could not install or start any created app** — it exits 1 while esbuild's install script is unapproved, and re-runs install before every `pnpm dev`. `create` now writes `pnpm-workspace.yaml` (`allowBuilds` for pnpm 11, `onlyBuiltDependencies` for 10, `packages: ["."]` because 9 rejects the file without it) and an `.npmrc` so `pnpm add` still works at the root. Checked install, add and build on pnpm 9.15, 10.34 and 11.8.

Still not verified: Windows; the live hosted endpoint (it serves the last deploy, so `detail` is not live until a redeploy); the created app's own GitHub workflow (it calls `pnpm/action-setup` with no version and `pnpm install --frozen-lockfile`, which an npm-created app has no lockfile for — left for the create-matrix work).
