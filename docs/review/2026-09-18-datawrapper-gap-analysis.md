# Datawrapper vs brand-ui (`charts`, `data`, `maps`) — gap analysis and recommendation

Date: 2026-09-18
Subject under review: Datawrapper (datawrapper.de) — 23 chart types, tables with mini-charts, choropleth / symbol / locator maps, the Academy (per-type "Customizing your …" articles), the blog's "Data vis do's & don'ts" series, and the curated **River favorites** gallery (app.datawrapper.de/river/favorites, read while logged in).
Packages under review: `packages/charts` (brand-ui 4.2.0, 27 containers + ChartFrame + AutoChart/ChartSpec + `/dashboard`), `packages/data` (`DataTable`), `packages/maps` (MapLibre canvas, `ChoroplethChart` lives in `charts`).

Method: fetched every Datawrapper chart-type product page and its Academy "Customizing your …" article, the Annotate / Layout / number-format / tooltip / embed / dark-mode / responsive-height articles and developer docs, ~40 blog posts (feature announcements 2016–2026 and the guidance series); opened 16 River favorites in a real browser at 380 / 600 / 751 / 900 px and read chart type, tooltip DOM and what appeared or disappeared per width; transcribed every public `*Props` interface in `packages/charts/src`, `DataTable` and the `maps` barrel on-device (read-only) and grepped for each "missing in ours" claim before writing it down. Items I could not confirm from a primary page are marked **[unverified]**; the five research files with per-setting tables and URLs sit beside this review in `docs/review/datawrapper/` (charts, tables+maps, blog+responsive, River field notes, our inventory).

The user's hypothesis was: "we have all the chart primitives but they lack detailed features and customization options, and our responsive design is bad." The source reading confirms both, and narrows them: **the primitive coverage is actually wider than Datawrapper's** (we ship 27 families to their 23 types; they have no heatmap chart, treemap, sankey, radar, gauge, distribution or network), but on every one of the ~14 concerns a Datawrapper author touches in the Refine / Annotate / Layout steps — axes, number formats, direct labels, legends, tooltips, annotations, colour keys, sorting, stacking modes, gaps, overlays, chrome, export, responsive height — our containers expose between a fifth and a half of the options, and **nothing inside a chart reacts to its own width except the bar category-axis fit cascade and LTTB decimation**. That second finding is the one to fix first because every other feature (end labels, annotations, legends, small multiples) needs a breakpoint to fall back on.

## 1. What Datawrapper actually is

An editor, not a library: a four-step wizard (Upload → Check & Describe → Visualize with Refine / Annotate / Layout tabs → Publish & Embed) whose output is a responsive iframe or `<datawrapper-visualization>` web component with derived height. Everything an author can set is a serialisable `metadata.visualize.*` key; the API exposes the same surface. Three product lines:

| Line        | Types                                                                                                                                                                                                                                                                                                                                                    | What carries the quality                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Charts (23) | bar, split bars, stacked bars, grouped bars, bullet bars · column, grouped, stacked, **multiple columns** (Feb 2025) · line, **multiple lines** (Feb 2024), area · scatter (bubble, trend line, custom lines/areas, connected) · dot, range, arrow plots · pie, donut, election donut, multiple pies/donuts · **dual-axis** and **waterfall** (Jul 2026) | per-type Refine settings (§3), the Annotate step (text annotations with 9-point anchors and connector lines, range highlights, reference lines), overlays (CI / value markers), numeral-style number formats, colour-by-column with an editable colour key                                                                                                                                                                                                                                                                                                                                     |
| Tables      | one type, three headline uses: data table, heatmap, table with mini-charts                                                                                                                                                                                                                                                                               | per-column format / style / width / show-on-desktop-or-mobile; four in-cell visuals (bar, sparkline, mini columns, heatmap); categorical conditional formatting; markdown / HTML / flags in cells; sticky first column and sticky rows; double-row header; search, pagination, ranks; card layout < 450 px                                                                                                                                                                                                                                                                                     |
| Maps        | choropleth, symbol (+ spike, arrow), locator                                                                                                                                                                                                                                                                                                             | 4 000 basemaps + 50 cartograms + custom TopoJSON; one shared colour-scale tool (continuous linear / median / quartiles / quintiles / deciles / natural; stepped equidistant / rounded / quantile / Jenks / custom) and one legend component (ruler / ranges / custom, h/v, 6 positions, hover-highlight, mobile relocation); place labels with collision; `{{ }}` tooltip templating with functions and HTML; crop-to-data, inset maps, pattern overlays; locator markers (point / line / area / arrow) with per-marker desktop / mobile visibility, marker key, scale bar, north arrow, globe |

What Datawrapper does **not** have, which we do: heatmap / calendar chart, treemap, sankey, network, tree, parallel coordinates, radar, gauge, bullet (as a chart, not bars), distribution (histogram / box / violin / strip), bump, candlestick, live line, gantt, a dashboard sheet, a serialisable chart spec with type inference, an in-package keyboard datapoint layer, a validating test double. Their "population pyramid", "bar-line combination", "timeline" and "connected scatter" are recipes on top of the base types, not types.

What Datawrapper has that is **out of scope for a component library** and not recommended below: the editor UI, the River reuse network, hosted publishing / oEmbed / iframe height postMessage, the basemap catalogue, paid custom themes, PowerPoint add-in, comments and workspaces.

### 1.1 What the best River examples all do (16 deep-dives, `docs/review/datawrapper/dw-river.md`)

1. **The title is the finding** ("Women live longer than men. By how much varies by country."); the metric definition is the description; the description is a real paragraph with bold phrases and, in several pieces, inline colour chips that replace the legend.
2. **Annotations do the explaining**: numbered ①–④ text blocks in reading order, coloured like the series they discuss; grey range highlights ("Covid-19"); dashed reference lines ("Global average: 73.8 years"); callouts with leader lines on maps; big in-panel delta figures ("+217 %").
3. **Direct labels over legends**: end labels, value labels at peaks, axis titles rendered inside the plot, culled automatically at 380 px. Legends appear only for categorical colour and are simple dot rows.
4. **Restrained colour**: one hue per panel, or one highlight versus grey, or one ramp. Grey for context regions and for the non-hovered lines.
5. **Quiet axes**: 3–5 y ticks, unit on the last tick only ("80 %", "$180", "+200 %"), abbreviated years ('10, '15), no axis lines except a darker zero baseline.
6. **Hover = focus**: hovered line stays, others fade to ~15 %; in small multiples a synced crosshair shows the date once and each panel's value; in column panels the value replaces the panel title.
7. **Consistent footer**: italic notes → "Chart | Map | Table: Author • Source: Name (link) • Get the data • Embed • Download image".
8. **Fixed authored height, content reflows inside it** (every chart is `vis-height-fixed`); small multiples collapse to one column; tables wrap, never hide, columns; text annotations either hide, re-wrap, or become a numbered marker with a key under the chart on mobile.

Everything in that list is a _feature of the renderer_, not of the author. Six of the eight are absent or manual in ours today.

### 3.2 Number and date formatting

Datawrapper: a dropdown of 16 presets plus numeral-style custom strings (`0.[0]`, `0a`, `+0`, `(0)`, `$0`, `0%`, `H:M`, `0,0e+0`), prepend / append text, 60 locales, separate tooltip formats. Ours: `ChartValueFormat = "number" | "compact" | "currency" | "percent"` through `Intl` with locale from `LocaleProvider`, set-consistent compaction (#250, which Datawrapper does not have and which we must keep), and `formatValue` function props scattered across ~8 components. Gap: no prefix / suffix, no explicit-plus, no parentheses negatives, no decimals control, no abbreviation control, no date-ladder. Proposal (RM-109): widen `ChartValueFormat` to accept an object `{ style, decimals, optionalDecimals, abbreviate, sign: "auto" | "always" | "parens", prefix, suffix, grouping }` on top of the four string presets, resolved once in `value-format.ts` so axis, labels, tooltip, legend and `MetricCard` stay in step; keep the set-consistency rule; add `dateFormat` presets. Do **not** implement a numeral parser — the object form covers every token in their list except `0,0e+0` and `H:M`, which stay function-prop territory.

### 3.3 Direct labels and value labels

Datawrapper: line labels "legend / right (direct, with connector) / none" that **fall back to a colour key on mobile**; automatic value labels first / last / all / "peaks and troughs" with a per-line count, outline and colour; bar values inside / outside / hover / always; scatter auto-labelling with collision avoidance and mobile thinning; "prevent label overlapping" default on. Ours: `Line.labelPeaks` (top-k peaks, `minGap` by index), `Bar.showValues` (`boolean | "outside" | "inside"`), `Scatter.labelExtremes`, `AreaChart.labelBands`, bump end labels; no series-name end labels on `Line`, no collision solver, no width-driven culling (`ours-inventory.md` §2 Annotations). Proposal (RM-110): one `labels` engine shared by line / area / scatter / bar — `seriesLabels: "end" | "key" | "none"` with an end-label layout (nudge, then leader, then fall back to key under `narrow`), `valueLabels: { placement: "first" | "last" | "all" | "peaks", perSeries, outline, matchColor }`, a pixel-space collision pass that drops by `labelPriority` and re-states dropped labels `sr-only` (the existing category-axis pattern).

### 3.4 Legends / colour keys

Datawrapper: on almost every type, position (pies: top / bottom / left / right), stacked list layout, values in key, drag-reorder and rename entries, merge same-colour categories, hover-highlight (dual-axis), ramp legends with hover marker (maps, table heatmaps). Ours: `ChartLegend` is a separate component the caller places anywhere; hover-link exists (`hoveredIndex`, `ChartLegendHoverProvider`); `onItemClick` renders buttons; **no `position`, no toggle-to-hide, not auto-rendered except `AutoChart`'s flat `<ul>`**; `HeatmapChart showLegend` draws a ramp key without a hover marker. Proposal (RM-118): `legend` prop on containers and `ChartSpec` (`{ position, layout: "row" | "stack", interactive: "hover" | "toggle", values }`) rendered by the container inside the measured box so it participates in height; `RampLegend` (continuous / stepped / custom labels, hover marker) shared by heatmap, choropleth, table heatmap cells and treemap sequential; size legend for bubbles.

### 3.5 Tooltips

Datawrapper: on/off, number and date format everywhere; a `{{ }}` template editor with `FORMAT`, `ROUND`, `CONCAT`, ternaries and HTML for scatter and maps; table-style tooltip in dual-axis; synced tooltips across small-multiple panels; focus behaviour (others fade, value replaces panel title). Ours: `ChartTooltip` is a shared-x crosshair tooltip with `rows` / `content` render props, `DateTicker` pill, cross-chart `hoverCategory` sync, family tooltips for heatmap / sankey / choropleth. Gap is not templating (React render props are strictly stronger) but the **presets**: no table layout, no focus / dim-others mode, no value-in-title mode, no tap-to-pin on touch. Proposal (RM-119): `ChartTooltip variant="rows" | "table" | "inline"`, `focus` on line / area / scatter (dim non-hovered series to the `SELECTION_EXCLUDED_OPACITY` rung — the mechanism exists for selection), touch pinning, and a documented `rows` recipe for "sentence" tooltips.

### 3.6 Annotations

Datawrapper (Annotate step, all charts since Nov 2020, bar family since Nov 2024): rich-text annotations positioned in **data coordinates** with a 9-point anchor, width as % of chart, connector lines with arrow heads, row anchoring for horizontal charts, desktop / mobile visibility and a **numbered-key fallback on mobile**; range highlights (solid or striped) and reference lines (1–3 px, solid / dotted / dashed) on both axes, "repeat in all panels"; scatter custom lines / areas from equations. Ours: strong primitives, no declarative layer — `Grid.highlightRowValues / highlightColumnValues` (+ labels), `AreaBand`, `ChartMarkers` (event icons at dates), `marks/` (`Marginalia` with wrapping and leaders, `Leader`, `HaloText`, `PeakRing`), family-specific `referenceLine(s)` on dumbbell / distribution / gauge / sparkline / waterfall callouts. Every one is placed by the caller in pixel or data space per family; nothing is on `ChartSpec`, so an agent cannot emit an annotated chart. Proposal (RM-111): `annotations: ChartAnnotation[]` on cartesian containers and on `ChartSpec` — `{ kind: "text", x, y, text, anchor, width, connector, color: "series:<key>" | token, showAt }`, `{ kind: "range", x1, x2 | y1, y2, label, pattern }`, `{ kind: "line", x | y, label, style }`, `{ kind: "row", category, text }` — rendered by one `ChartAnnotations` layer built on the marks, with the narrow fallback (numbered marker + key below the plot, reading order = array order). This is the single item that most changes what the River examples look like on our stack.

### 3.7 Colour

Datawrapper: base colour → shades, per-element customisation with multi-select, colour-by-column, editable colour key, LCH picker, 8-digit hex opacity, colour-blind check, palette tool for scales (6 sequential + 3 diverging built-ins, custom stops, lightness autocorrect, presets). Ours: token-only (`--chart-1..12`, seq / mono / div ramps, accent), `palette` prop, `highlightKey` hero pattern, high-decoration hatch / dash / marker auto-differentiation, dark mode by theme tokens, selection tri-state inks — this is the one area where **our discipline is the right answer** and Datawrapper's freedom is a liability (their blog spends twelve posts telling authors to use fewer colours). Gap: `colorBy` (a categorical column colouring marks) exists only as per-datum overrides (`PieData.color`, `rowColor`, `getFeatureColor`); no numeric colour scale outside heatmap / treemap; no "grey everything except" one-liner. Proposal: `colorBy: { key, scale: "categorical" | "sequential" | "diverging", steps?, method?: "linear" | "quantile" | "jenks" }` on bar / scatter / dumbbell / choropleth (RM-113, RM-115, RM-124) resolving to the existing ramps; `emphasis={{ key | predicate }}` as the documented spelling of highlight-vs-grey. No picker, no hex.

### 3.9 Chart chrome, export, embed, dark mode

Datawrapper: title (hideable), description, notes (HTML), source + URL, byline, alt text; footer with data download, image download, embed, attribution; PNG at 1–4×, PDF / SVG (paid) with CMYK; script / responsive-iframe / plain-iframe embeds; automatic dark mode with contrast-preserving conversion and `?dark=` override. Ours: `ChartFrame` has `title / description / source`, expand modal, table flip, CSV, SVG, PNG 2×; **export clones only the `<svg>`, so HTML-portaled axis labels, legends, title and description are not in the picture** (`export-svg.ts` `findChartSvg` → `container.querySelector("svg")`, confirmed on-device); no notes / byline / alt text; dark mode through tokens (correct). Proposal (RM-117): `notes`, `byline` with kind prefix, `source: { name, href }`, `altText` wired to `accessibleDescription`, `actions`, footer layout; make the exported SVG complete by rendering axis and legend text into the SVG at export time (a hidden export layer, or `foreignObject` with inlined styles — decide in the item), scale option 1–4×. Not recommended: iframe / postMessage height, oEmbed, PDF.

### 3.10 Accessibility

Datawrapper auto-generates a screen-reader description for line and scatter charts and has an alt-text field and a colour-blind checker; keyboard navigation is **[unverified]**. Ours already has `role="figure"` + description, the keyboard `ChartDatapointLayer`, table flip, sr-only restated labels, auto summaries for heatmap / network / distribution / unit, `motion-reduce`. Parity item: auto summaries for line / bar / scatter / pie through the same seam as heatmap (folded into RM-110 since it needs the label engine's "what is notable" pass), and `altText` on the frame (RM-117). No gap in the other direction.

## 4. Responsive design — their model, ours, and the design to adopt

### 4.1 Their model (Academy, developer docs, and what the browser showed)

- **Element width, never viewport.** The iframe is `width:0; min-width:100%`; the chart measures its own box. Editor previews are "mobile / tablet / desktop" plus a drag handle; the Academy quotes 380–400 px mobile and ~700 px desktop. No published breakpoint list except tables (card layout under 450 px).
- **Height is always derived and authored per plot, never per box.** Bars / dots / tables grow with rows; pies and maps derive from width; for line / area / scatter / column the author sets a _plot_ height as fixed px or as % of width (since Mar 2024). The plot excludes header, colour key, annotation key and footer, so a wrapping title never squeezes the data. Total height = header + key + plot + annotation key + footer, pushed to the host.
- **Reflow, don't scale.** Fonts never change size. What changes: x ticks thin (9 → 4 at 380 px), y ticks thin (5 → 3), line end labels move into a top key, value labels and scatter labels are culled by collision (some become mobile-only), text annotations hide / re-wrap / become numbered markers with a key below, small multiples collapse to one column (separate desktop and mobile column counts), tables wrap and hide per-column, map legends leave inside corners for below-the-map, symbol sizes reduce, annotation widths are % of chart width.
- **Per-breakpoint author overrides**, everywhere the same two words: "show on desktop / mobile" for annotations, table columns, facet panels, locator markers; separate panel counts; plot height per device.
- Weak spot they share with us: aspect-locked maps become unreadable at 380 px (Lake Ontario).

### 4.2 Ours today (precise, from `ours-inventory.md` §3)

Sizing is visx `ParentSize` (10 ms debounce; 100 ms on bar / area / radar) or `react-use-measure`, inside a `style={{ aspectRatio: "2 / 1" }}` box; `ChartFrame` fixes the body at 260 px regardless of width unless `chrome="tile"`. The only width-driven behaviours are the category-axis fit cascade, LTTB decimation to `max(64, width·1.5)` points, tick-label de-duplication and tooltip clamping. Tick count, fonts, margins, legend placement, date format, annotation placement and pie / ring layout are all static; `aspectRatio` is an author prop (default `"2 / 1"`), never width-reactive. Simplification happens only through the host-supplied `density` tier (`xs | sm | md | lg`), which only the dashboard sheet computes (from tile pixels). A standalone `<LineChart>` on a phone renders exactly as on a desktop, at half the width, with the same five ticks and a 2:1 box that is 190 px tall. `MetricGrid` is the one place with viewport media queries, which is the wrong axis for a component that can sit in a sidebar.

### 4.3 The design to adopt (RM-107, ADR 0039)

1. **One breakpoint source, container-measured.** `useChartBreakpoint()` derives `narrow` (< 480 px), `compact` (< 768 px), `wide` from the width `ParentSize` already reports, published on the chart context and as `data-chart-breakpoint` on the container. Families read it; hosts may force it (`breakpoint="narrow"` for storybook / export). `density` stays host-driven but `narrow` auto-implies at most `sm` behaviours where the two overlap (ticks, legends).
2. **`Responsive<T>`** — every prop that Datawrapper offers "per device" takes `T | { base: T; narrow?: T; compact?: T }`: annotation `showAt`, facet `columns`, legend `position`, `plotHeight`, table column `showAt`, marker visibility.
3. **Plot height, not box height.** `plotHeight: number | { aspect: number }` (fixed px or width-relative), responsive; `ChartFrame` computes total = chrome + legend + plot + annotation key and stops fixing 260 px (`height` stays as a deprecated alias mapping to `plotHeight`). Default plot aspect becomes taller under `narrow` (1.25 : 1 instead of 2 : 1) — the River charts do exactly that.
4. **Reflow rules per family**, each a named test: tick targets from width and height (§3.1), date ladder (§3.2), end labels → key (§3.3), annotations → numbered key (§3.6), legend `position` collapses to top-stacked, facets → one column, pie / ring drop outside labels for a key, map legends leave corners, symbol radius scales by `sqrt(width / 700)`.
5. **Fonts do not scale.** Tokens stay; readability comes from fewer, not smaller, labels.
6. **Gate.** A Storybook viewport matrix (380 / 600 / 900, light / dark) with Playwright screenshots for every family and a contract test asserting `data-chart-breakpoint` flips at the thresholds. The maintainer's standing rule applies: harness-green is not done; the validator drives the story at 380 px and quotes tick counts and label counts.

Not adopted: viewport media queries, iframe embedding, height postMessage, a mobile-specific title.

## 7. Chart-choice guidance to fold into `chart-selection.md` and `inferChartType`

From `dw-blog-responsive.md` §B, the rules that change what we _default_ to, not only what we document:

- Title states the finding; description holds the metric definition (RM-117 docs, `ChartSpec.title` guidance).
- Bars for absolute values; dot plot when > 2 values per category; split bars / pyramids for mirrored comparisons.
- Pies: ≤ 5 slices, group the rest as "Other", never two values → `inferChartType` already prefers bars; RM-114 adds the grouping default.
- Stacked columns: most important series at the bottom, ≤ ~10 totals, no total as a series → `stackOrder` default and a dev warning (RM-113).
- Area charts only for a breakdown of a total over time, always zero-based (we do); skip for a single series → inference rule (RM-126).
- Spaghetti lines → small multiples; faint "all lines" in the background; same y-scale by default and warn when independent → RM-120 defaults.
- Line charts need not start at zero, but consider it near zero; avoid natural / cardinal interpolation → RM-112 changes the `Line` default curve from `curveNatural` to monotone with a CHANGELOG note.
- Never rotate labels as a first resort → keep the fit cascade; add wrap before tilt (RM-108).
- ≤ 7 colours; grey by default; one highlight; de-emphasise with the same hue at lower saturation → `emphasis` spelling (§3.7).
- Dual axes: only for expert readers, different units, proportional or both-zero scales, different mark types, colour-matched axis labels → RM-121 encodes these as defaults, `inferChartType` never infers dual-axis.
- Bar over column on small screens → not automated by Datawrapper either; document, don't switch.
- Repeat units in axis labels, tooltips and annotations; abbreviate (12.8k); exact values in tooltips and downloads → RM-109 `unit` and set-consistent compaction.

## 8. Recommendations

### A — Foundations (do first; every other item stands on them)

1. **Responsive contract** (RM-107, ADR 0039): container breakpoint, `Responsive<T>`, plot-height model, reflow rules, viewport gate.
2. **Axis engine** (RM-108): domain, ticks, log / sqrt, titles inside / outside, grid modes, top / right positions, width-derived tick targets, wrap rung.
3. **Format engine** (RM-109): object `valueFormat`, `unit` once, date ladder.
4. **Label engine** (RM-110): end labels with key fallback, automatic value labels, collision pass, auto summaries.

### B — Richness on existing families

5. **Declarative annotations** (RM-111) — the highest-leverage single item after the contract.
6. Line / area (RM-112): gaps, curves by name, outline, symbols, focus hover, fill between lines.
7. Bar / column (RM-113): percent and diverging stacks, sort, group-by, colour-by, track bars, overlays, comparison columns, totals.
8. Pie / donut (RM-114): labels, grouping, sort, half-donut preset, legend position.
9. Scatter (RM-115): bubble size, colour / shape by column, trend line, custom lines.
10. Dot / range / arrow (RM-116): arrow variant, N dots, sort and group.
11. Frame chrome + complete export (RM-117); legend engine + ramp legend (RM-118); tooltip presets (RM-119).
12. **Small multiples** (RM-120); **dual-axis** (RM-121); waterfall parity (RM-122).

### C — Tables and maps

13. `DataTable` presentation layer (RM-123).
14. Thematic map layer on `ChoroplethChart` (RM-124); locator furniture on `maps` (RM-125).

### D — Guidance and closure

15. Chart-selection reference, inference rules, River recipes in Storybook (RM-126); closure (RM-127).

### Explicitly not recommended

The editor, colour picker and hex freedom (our tokens are the better contract), iframe / postMessage embedding and oEmbed (we are a library, hosts own layout), PDF / CMYK export, the basemap catalogue (ship fixtures and document TopoJSON upload), a `{{ }}` tooltip language (render props are safer and stronger), viewport media queries, the River.

Wave 0 — RM-107, RM-108, RM-109 in parallel (108 and 109 do not need 107's breakpoint to land their APIs; their width-aware defaults switch on when 107 merges). Wave 1 — RM-110, RM-111, RM-112, RM-113, RM-114, RM-115, RM-116 (seven in parallel, disjoint families; 110 and 111 are opus). Wave 2 — RM-117, RM-118, RM-119, RM-120, RM-121, RM-122. Wave 3 — RM-123, RM-124, RM-125 (parallel, three packages). Wave 4 — RM-126, RM-127.
